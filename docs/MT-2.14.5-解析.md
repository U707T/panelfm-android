# MT 管理器 2.14.5（v8a · clone-MOD）UI / 功能 / 逻辑解析

> 分析对象：`/workspace/MT-Manager_2.14.5_v8a.apk`（27.6 MB）
> 目的：为 `/workspace/panelfm-android`（Kotlin + Compose 原生双窗格文件管理器）提取**可复用的 UI 结构、功能语义与交互逻辑**
> 方法：`aapt2 dump` 解出 AndroidManifest / resources.arsc / 385 个布局；androguard 解出全部布局 XML 并做「资源 ID → 中文文案」还原；dex 字符串/类名与 assets 语法文件交叉验证。
> 产出：本文 + `mt_strings_zh.txt`（2007 条中文文案）/ `menus_zh.txt`（33 个菜单）/ `layouts/`（385 个反解布局）/ `resolved/`（文案已还原的布局）

## 1. 主界面（双窗格）——布局与结构

### 1.1 顶层结构（`0x7f0c0032` = 主 Activity 根布局）

```
l.____ (id 090126)  ← 顶层容器（承载左右滑出的 SideSheet）
├─ include 0x7f0c0033  ← 双窗格主体
└─ include 0x7f0c0035  ← 侧拉栏（layout_gravity=START，宽 -1）
```

### 1.2 双窗格主体（`0x7f0c0033`，86 个 id，全应用最复杂）

```
ConstraintLayout
├─ 顶部条容器 (id 09046B)          ← 每窗格自己的「路径栏 + 标签页」宿主
│   └─ 自定义 View (09038A)        ← 标题/路径（居中）
├─ Guideline (0900B2) = 50%        ← 左右分界（可拖动）
├─ shadow_left/right (0903A1/0903A4, 5dp) + shadow_*_top/bottom  ← 活动窗格投影
├─ divider_left/right (090111/090112, 1px)
├─ 左窗格容器 (0901E2)             ← 内含 RecyclerView (0901FE, divider=1px)
│   ├─ FAB (090166) bottom|end, margin=12dp        → 图标 0x7f080124 = 剪贴板
│   └─ FAB (09016A) bottom|end, marginBottom=74dp  → 图标 0x7f080110 = ✕
├─ 右窗格容器 (0901E3)             ← 同上（0901FF / 090167 / 09016B，图标同左）
├─ 左/右 加载遮罩 (09020D/09020E)：bg #66222222 + ProgressBar + 「取消」按钮 + 百分比文字(10sp)
├─ 顶部条 (09007B) = include 0x7f0c0034
└─ 底部条 (09007F) + 工具栏 (090080)
```

> 图标语义已逐一核对（vector pathData）：`0x7f080110` = `M19,6.41L17.59,5 12,10.59 …`（**✕**）、`0x7f080124` = 剪贴板轮廓（**粘贴**）、`0x7f08010D` = `M19,13h-6v6h-2v-6H5v-2h6V5h2v6h6v2z`（**＋**，仅出现在 `0x7f0c004c` 的 FAB）、`0x7f08012C` = `M2.01,21L23,12 2.01,3…`（**发送/前进箭头**）、`0x7f08012A` = 九宫格。
> 其它布局的 FAB 组合：`0x7f0c0024`（分页界面）= ✕(136dp) / 九宫格(74dp) / 箭头(12dp)；`0x7f0c0172` = ✕(136dp) / 九宫格(74dp) / 垃圾桶(12dp)；`0x7f0c0176` = 编辑笔(198dp) / 九宫格(136dp) / 垃圾桶(74dp) / 垃圾桶(12dp) —— **FAB 栈按 marginBottom 74dp 步进**是 MT 的统一约定。

**可直接复用的 6 条结构结论**

1. **每个窗格自带两枚 FAB（bottom|end，按 marginBottom 步进 12dp / 74dp）**：
   - 靠下（`android:layout_margin=12dp`，id 090166/090167）= 图标 `0x7f080124` = **剪贴板**
   - 靠上（`android:layout_marginBottom=74dp`，id 09016A/09016B）= 图标 `0x7f080110` = **✕**
   > 原始布局只给了图标与位置，**语义靠推断**：剪贴板 → 「粘贴到当前目录」；✕ → 「取消/退出当前状态（多选等）」。两者都 `visibility=visible`，由代码按状态显隐。
   > PanelFM 目前**只有底栏 `＋`，没有剪贴板粘贴入口**（已核实：`app/.../ui/browser/` 内无任何 `ClipData`/粘贴逻辑）。
2. **加载态是「遮罩 + 转圈 + 取消 + 百分比」**（`#66222222` 半透明黑、文字 10sp、按钮「取消」），而不是简单骨架屏 —— 大目录/网络目录加载时的可取消进度。
3. **分界线 = 1px 实线 + 5dp 渐变阴影**，且**阴影只在活动窗格一侧亮起**（`shadow_left` vs `shadow_right` 两组 drawable）→ 用「阴影 + 顶栏高亮」表达焦点，而非整体调透明度。
4. **两个窗格的列表分隔线是 1px**（`dividerHeight=1px`）、**行高固定**。
5. 窗格顶部条内含 **TabLayout（0903F9）+ 更多(0902B2) + 新建页(090116) + 可横向滚动的「动作按钮条」（09022F）**；动作条里前三项硬编码为 **复制 / 移动 / 删除**（见 §1.3）。
6. 底部条分两层：`09007F`（容器）+ `090080`（左下角工具条，用于「选择当前目录」等模式化操作）。

### 1.3 顶部动作条（`0x7f0c0034`）——MT 的「当前选中项快捷动作」

```
LinearLayout(350dp 高, id 09007C)   ← 顶部条整体
├─ TabLayout (0903F9)                        ← 标签页
├─ FrameLayout 更多 (0902B2) + ImageView     ← ⋮
├─ FrameLayout 新建页 (090116) + ImageView   ← ＋
├─ HorizontalScrollView (09022F)
│   └─ LinearLayout
│       ├─ 复制 (09022C)  图标22dp + 文字14sp
│       ├─ 移动 (09022D)
│       └─ 删除 (09022E)
└─ 1px 分隔线 (0903F8)
```

> 逻辑：**选中项后，顶部出现「复制 / 移动 / 删除」三连**；未选中时这一行隐藏。
> 对应菜单 `0x7f0e0000`：`导出` / `隐藏新增加文件` / `隐藏已删除文件` / `隐藏被修改文件`（这是「文件夹对比模式」下的菜单）。

### 1.4 侧拉栏（`0x7f0c0035` + `0x7f0c0046` / `0x7f0c0052`）

```
0x7f0c0046 / 0x7f0c0052（含 NavigationView）:
├─ 顶部条 (09046B)                       ← 应用图标 + 名称 + 主题副标题 + 右上 ⋮
├─ NavigationView(layout_gravity=START)
│   ├─ 头部 (090127) + 3dp 渐变线
│   ├─ 列表 (090357)
│   └─（0x7f0c0052 版）底部「最小化」按钮 (0902A9)
└─ FAB (09016C)
```
`0x7f0c0028` 另有一版：`include 0x7f0c0029（主内容） + 0x7f0c002F（左侧符号/编辑面板） + 0x7f0c002A（右侧检查面板）` —— 这是**文本编辑器/Dex 编辑器**的三栏结构。

**侧拉栏三段（从文案与 ⋮ 菜单还原）**

| 段 | 条目 | 依据 |
|---|---|---|
| 本地 | 根目录 / 内部存储 / 外置存储 / 各「本地存储」（可隐藏） | `0x7f1105ec` 根目录、`0x7f110689` 内部存储、`0x7f110629` 外置存储、`0x7f1102ec` 「本地存储被隐藏后…」 |
| 网络 | 各网络存储（可隐藏地址），点开在**活动窗口**打开 | `0x7f1104b2` 网络存储、`0x7f1102e9` 在侧拉栏隐藏地址 |
| 后台 / 工具 | 后台（任务）、书签、终端、插件、工程… | `0x7f1100cc` 后台、`0x7f1100da` 书签、`0x7f1106d0` 终端模拟器、`0x7f1105f5` 「保存为工程后…可以在主界面的侧拉栏中重新打开工程」 |

**侧拉栏右上 ⋮（四条）**：`主题跟随系统`（勾选）· `添加网络存储 ▶`（协议子菜单）· `添加本地存储` · `管理工具分组`（+ `设置`）— 依据 `0x7f110214 / 0x7f110212 / 0x7f110211 / 0x7f110213`。

### 1.5 底部命令栏

- **`0x7f0c0034` 的动作条**已覆盖「复制/移动/删除」；底栏本体在 dex 中动态构建（布局里以 `09007F` 容器占位）。
- 文案证据：`0x7f11028f`「**长按底部的「同步」按钮也可以进行过滤**」、`0x7f1100e0`「从底部工具栏上滑可拉出书签…可适当增加下边距」、`0x7f1100dd/e`「底部工具栏增加下边距 / 下边距大小」。
- 因此 MT 底栏语义 = **后退 · 前进 · 新建 · 同步 · 上级** + 多选态 `全选/反选/类选/…`（`0x7f11062b/632/633` 全选/反选/类选），**长按「同步」= 过滤**，**上滑 = 书签**。
- 底栏下边距可调（`0x7f1100de` 底部工具栏下边距大小），且**与书签手势冲突时建议加大**（`0x7f1100e0`）。

## 2. 核心交互逻辑（MT 独有、PanelFM 可直接抄的语义）

### 2.1 选择 / 多选手势（文案原文即规格）

| 文案 | 资源 | 语义 |
|---|---|---|
| 滑动选择列表中任意两个文件，将会自动选择它们中间所有的文件。 | `0x7f11062f` | **滑动跨行 = 区间选择** |
| 开启后点击列表中任意两个项，将会自动选择它们中间所有的项。 | `0x7f110630` | 点击两次 = 区间选择（可选开关） |
| 可通过分别长按两个项目来进行连选 | `0x7f110631` | **长按两项 = 连选区间** |
| 左右滑动文件可直接选择 | `0x7f1106f3` | 横滑 = 多选（PanelFM 的 24dp 右滑即此条） |
| 右滑列表项可进行更多操作 | `0x7f110697` | 右滑出操作 |
| 长按打开菜单 | `0x7f1103a9` | 长按 = 菜单 |
| 已选: %d | `0x7f11063b` | 多选计数 |

> 结论：MT 的多选是 **「长按 = 锚点；再长按第二项 = 连选；滑动跨行 = 区间选择」** 三合一，且**滑动选择是"自动全选区间"而非"逐项加选"**。PanelFM 已有「右滑 ≥24dp 进多选 + 滑动区间选择」，建议补 **「长按两项连选」**（低风险、纯手势层）。

### 2.2 冲突与文件存在处理（MT 的三选项，与 PanelFM 的「覆盖/跳过/保留两者」不同）

`0x7f0c0098`「文件已存在」对话框 = **三个单选**：
- `复制并替换`（默认，`0x7f110264`）
- `跳过该文件`（`0x7f11028a`）
- `复制但保留两个文件`（`0x7f110265`）

另有 `为后续冲突执行相同操作`（`0x7f1100a5`）勾选项，以及「**覆盖全部 / 跳过全部**」（`0x7f110269/289`）。
移动场景措辞为 `移动并替换`（`0x7f110270`）/`移动但保留两个文件`（`0x7f110271`）。
> 可用点：PanelFM 冲突框文案可改成 MT 的「复制并替换 / 跳过该文件 / 复制但保留两个文件」+「为后续冲突执行相同操作」，语义等价但更贴 MT。

### 2.3 批量重命名（`0x7f0c0099`）

- 三段式：**表达式输入框**（recordKey=`rename_multi_pattern`）+ **查找内容 / 替换内容** 双列 + 「使用正则表达式查找替换」勾选。
- 变量说明（`0x7f1105bc` 原文）：
  - `{P}` 文件名前缀（abc.txt → abc）
  - `{S}` 文件名后缀（abc.txt → .txt）
  - `{N}` 从 N 开始递增（{0}、{1}）
  - `{zN}` 同 {N} 但补 0 对齐（{z8} → 08、09、10、11…）
  - 「**不使用替换功能请将查找内容留空**」
- PanelFM 现状：已实现 `{P}{S}{T}{N}{zN}`，**缺「查找/替换（含正则）」这一半**，且未把「替换留空 = 纯表达式」的说明写清。

### 2.4 排序（`0x7f0c00c8`）

- 标题「排序方式」，**2×2 单选**：`按名称 / 按大小` `按日期 / 按类型`。
- 两个勾选：`仅应用于此文件夹`（`0x7f110428`）、`逆向排序`（`0x7f11067c`）。
- PanelFM 已对齐（含「管理」）。**唯一差异**：MT 标题不带「- 左/右窗口」，PanelFM 带；属可选。

### 2.5 搜索（`0x7f0c009a` + `0x7f0c009b` + `0x7f0c0078/0087`）

`0x7f0c009a`（文件搜索）结构：
```
标题「搜索」
├─ 提示「欲搜索文件名 (支持通配符*和?)」 + 输入框（默认 "*"，recordKey=file_search_record）
├─ ☑ 搜索子目录（默认勾选）
├─ ☐ 高级搜索
│   └─（展开）按文件大小过滤：[无限制]-[无限制]（点选弹出 0x7f0c009d「选择文件大小」）
│              文件中包含内容 + 输入框
│              ☐ 区分大小写  ☐ 正则表达式
```
- `0x7f0c009d`「选择文件大小」= 预设档位网格（100KB / 256KB / …）。
- 「搜索结果(%d)」`0x7f11061f`、「搜索结果数量过多，已停止搜索」`0x7f110620`、「停止搜索」`0x7f110686`、「二次搜索」`0x7f110628`、「在当前结果中搜索」`0x7f110619`、「清除搜索」`0x7f110123`。
> 可用点：PanelFM 缺「**搜索结果条数上限提示 + 停止搜索**」的显式反馈，以及「**在当前结果中二次搜索**」。

### 2.6 属性（两套）

- 简单版 `0x7f0c00e1`：名称 / 目录 / 类型 / 大小 / 修改时间 / 权限 / 所有者 / 用户组 / 文件数 / 文件夹数（`headerName…headerFolderCount` 即 §5 的 id 命名表）。
- 完整版 `0x7f0c0097`（88 id）：在简单版基础上加 **CRC32 / MD5 / SHA1 / SHA256 / HASH / 压缩后大小 / 签名状态 / 加固状态 / 链接指向 / 可用空间**，且用 **Barrier + ConstraintLayout** 做「标签列 → 值列」自动对齐（`barrierDirection=1`）。
- PanelFM 现状：已有名称/目录/类型/大小/时间/权限/所有者/用户组/文件数/文件夹数/位置/ETag/链接指向/可用空间/复制路径。**缺：CRC32（MT 校验值菜单里 CRC32 与 MD5/SHA1/SHA256 并列，`0x7f030009` 数组「复制为 十六进制/十进制/二进制/Ascii/Base64/SHA1/MD5/CRC32」）**。

### 2.7 解压（`0x7f0c00ce`）

标题「解压」
├─ ○ 解压到单独的文件夹（默认隐藏，仅特定场景显示）
├─ ○ 解压到当前目录
├─ ● 解压到文件夹…（默认选中）

### 2.8 压缩（`0x7f0c0080`）

```
标题「创建压缩文件」
├─ 文件名
├─ 格式 (Spinner)      ← 依据 0x7f030020 数组：仅存储/极速压缩/快速压缩/标准压缩/最大压缩/极限压缩/APK模式（这是压缩级别）
├─ 压缩级别 (Spinner)

```
> 可用点：PanelFM 压缩对话框**缺「压缩级别」与「密码 / 加密文件名」**（当前只有格式选择）。

### 2.9 打开方式（`0x7f0c00c3`）

- 标题「打开方式…」，右上放大镜（🔍 搜索）。
- 内容为 **FrameLayout + 三列网格**（`0901FE` clipToPadding=false）。

## 3. 网络存储（编辑连接）——四套表单的精确字段

四张布局（`0x7f0c0082` WebDAV / `0x7f0c00c6` SFTP / `0x7f0c00c7` SMB / `0x7f0c009f`、`0x7f0c00a0` FTP·FTPS）**共用同一套 Material `TextInputLayout` 模板**（`expandedHintEnabled=false`、`passwordToggleEnabled=true`），字段顺序如下：

### WebDAV（`0x7f0c0082`）
`URL`（hint 示例 `https://dav.xxx.com:443/dav`）→ `用户名`（可空）→ `密码`（可空，👁）→ `初始路径`（可空）→ `备注` → ☑ `信任所有 HTTPS 证书` → ☑ `在侧拉栏隐藏地址`

### SFTP（`0x7f0c00c6`）
`主机` → `端口`(maxLength=5, number) → `用户名` → ☐ `使用密钥登录`（右侧 `…` 选文件按钮）→ `密码`（👁）→ `密钥`（多行 5 行文本框，与密码二选一，用 Barrier 控制显隐）→ `初始路径` → `备注` → `编码` → ☑ `在侧拉栏隐藏地址`

### SMB（`0x7f0c00c7`）
`主机` → `端口` → `域`（可空）→ `用户名`（hint=`anonymous`）→ `密码`（可空，👁）→ `初始路径` → `备注` → ☑ `在侧拉栏隐藏地址`

### FTP / FTPS（`0x7f0c009f`、`0x7f0c00a0`）
`主机` → `端口` → `用户名` → `密码` → `初始路径` → `备注` → `编码` → ☑ `在侧拉栏隐藏地址` → **`传输模式`：被动 / 主动** → **`加密模式`：显式 / 隐式**

**连接测试文案**（`0x7f1104b8 / 2b7 / 4bf`）：
- `正在测试读取文件列表…`
- `正在测试读取文件列表… (如果卡在这一步，请尝试切换主/被动模式)` ← **MT 把"卡住"的诊断提示写进了 loading 文案**
- `测试成功`
- `请输入主机名 / 请输入密钥 / 请输入密码 / 请输入URL`（分协议校验）
- `编码名称不存在`、`已设置为该网络存储的初始路径`、`未找到对应的网络存储配置，可能已被您删除或修改`、`不支持打开网络存储路径`

**设置里还有**：`使用 API 访问外置存储`（`0x7f11072a`）、`使用 Document API 访问外置存储、USB 设备`（`0x7f11072b`）、`请求 Root 权限`/`请求 Shell 权限`（`0x7f1105ce/5d0`，Shizuku）、`注入文件提供器`（`0x7f0c00a8`，无 ROOT 访问 data）。

> 与 PanelFM 的差异（**建议补齐**）：
> 1. **FTP/FTPS「编码」字段**（文件名编码，中文 FTP 服务器必需）——PanelFM 无。
> 2. **连接测试的「卡住提示」文案**（主/被动模式切换引导）——PanelFM 无。
> 3. **「已设置为该网络存储的初始路径」**：在浏览界面某菜单把当前路径设为该连接的初始路径 —— PanelFM 无。
> 4. `端口 maxLength=5` 的输入约束、密码 `可空` 占位提示 —— 细节。
> 5. WebDAV 的 `URL` 单行自动解析（PanelFM 已做，✅）。

### 6.1 对话框视觉规范（可直接数值化）
- 标题：`TextView id=090464`，`ellipsize=3`、`textAlignment=5`（居中）、`style=?android:0101005B`（系统对话框标题样式）、上下 padding `?7F04017D`。

- **对话框图标有 3 种背景模式**（深色自适应 / 浅色自适应 / 无背景）——PanelFM 未做。

### 6.2 输入框带历史记录（`app:recordKey`）
MT 自定义输入控件带 `recordKey` 属性，**自动记住历史值**：`file_search_record`、`filter_record`、`rename_multi_pattern/search/replace`、`java_search`、`xml_search/xml_replace`、`hex_search_content/hex_replace_content`、`pool_replace`、`arsc_search_value`。

### 6.3 快捷键栏（`0x7f0c004f`）
终端/编辑器的**两行软键盘**：`Esc Tab PgUp Home ▲ End ⋮` / `Ctrl Alt PgDn ◀ ▼ ▶ ⇄`，每个 `layout_weight=1`、`height=@7F070338`。另含 `取消 / 确定` 内联条与「输入框 + 上个/下个」查找条。

### 6.4 编辑器的「检查」面板（`0x7f0c002a/002b`）
`大端模式` 勾选 + `字节 / 字节(无符号) / 短整数 / 短整数(无符号) / 整数 / … / UTF8 字符串 / Unicode 字符串`（`0x7f1102e0…2e6`）逐行展示 —— 即 **Hex/数值解释器**（数据检视面板）。
> 可用点：PanelFM 的 Hex 只读视图**可以加这个「数值解释」侧栏**（只读，不涉及编辑）。

### 6.5 语法高亮是声明式 DSL（`assets/syntax/*.mtsx`）
22 个文件，语法形如：
```
{
    name: ["Kotlin", ".kt"]
    comment: {startsWith: "//"}
    comment: {startsWith: "/*", endsWith: "*/"}
    contains: [
        { color: "string", start: {match: /"""/}, end: {match: /"""/} }
        {builtin: #JAVA_QUOTED_STRING#}
        {builtin: #JAVA_NUMBER#}
        {match: /@\w+/, 0: "meta"}
        {match: keywordsToRegex("as break class …"), 0: "keyword"}

```
`init/colors.mtsx` 定义 **日/夜双色**（`"default" #000000 #A9B7C6` 等 18 个语义色）；`init/builtins.mtsx` 定义可复用片段（`#JAVA_QUOTED_STRING#` 等）。
> 可用点：PanelFM 的 `SyntaxLexer.kt` 是硬编码 14 种语言。**若未来要支持用户自定义语法，MT 的这套 DSL 是最佳参考**（键名：`name/colors/comment/lineBackground/contains/color/start/end/match/builtin/number/keywordsToRegex`）。当前不必做。
