## 0. 结论：能做，但不是换皮

能做，而且比想象中便宜 —— 因为当前 UI 的"脏"主要不是颜色和字号，而是**信息架构靠文案打补丁**。
只改配色/圆角会失败；按下面四刀动布局，视觉层级会从 4 层降到 2 层，代码净减约 600 行（估算）。

但有 **3 个前提需要拍板**，它们不是技术问题：

| # | 前提 | 说明 |
|---|---|---|
| 1 | **放弃"MT 观感对齐"，保留"MT 交互对齐"** | README §6 写的是"布局结构、尺寸色值、图标 pathData、交互文案"都对齐 MT。Clean 版会改掉前三项，只保留双窗格、长按菜单、滑动多选、上拉书签这些**肌肉记忆**。这是产品身份的选择，不是 UI 细节。 |
| 2 | **删掉首页** | 不是审美决定：`HomeScreen` 目前**不可达**（`onOpenHome` 传进 `DualPaneScreen` 后没有任何调用点），553 行是死代码。删它是纯收益。 |
| 3 | **双列模式下列表只显示文件名** | 时间/权限/大小移到单列模式右侧或「属性」。这是"一行一信息"的硬约束；不接受的话，Clean 1.0 的密度优势会打对折。 |

其余全部可以在 `ui/` + `core/ui/` 内完成，不碰 VFS / 传输 / 数据层，不需要新依赖，不需要升 Compose。

## 1. 审计：现在的"不干净"不是配色问题

### 1.1 数字（2026-11-18 实测，v2.4.4）

| 指标 | 现状 | 说明 |
|---|---|---|
| 代码规模 | 205 个 Kotlin 文件 / 4.83 万行 | 不含测试 |
| `ui/` 里直接可见的中文 `Text("…")` | **349 条** | 其中 ≥12 字 106 条、带句读 71 条 |
| `subtitle =` 调用 | **41 处** | 列表行 / 设置项的第二行 |
| `labelSmall + onSurfaceVariant` 说明段 | **36 段 / 17 个文件** | 设置页独占 10 段 |
| `contentDescription`（非空） | **32 处** | 无障碍与自动化的唯一抓手 |
| `testTag` | **0 处** | 智能体/UI 测试无法稳定定位任何控件 |
| 每行视觉元素 | 28dp 彩色底板 + 13sp 名称 + 10sp 副标题 + 1px 分割线 | 40dp 高，4 个元素 |
| 顶栏 | 深色 #151515 + 路径 18sp + 统计 12sp | 统计行常驻 |

### 1.2 四个结构性问题（文案只是症状）

1. **同一份内容两套实现**：`HomeScreen`（553 行）与 `SideDrawer`（532 行）都在列 本地卷 / 网络连接 / 工具，
   各自有一套空态文案、一套 About、一套长按菜单。而首页目前**不可达** ——
   `AppRoot.kt:383` 把 `onOpenHome = { push(Screen.Home) }` 传进 `DualPaneScreen`，
   但后者只声明参数、从不调用。553 行死代码 + 一份重复文案。
2. **"顶栏永远深色"是一条横切规则**：5 套主题 × 2 模式都要配 `topBar` 色；
   每个页面还要手动切状态栏图标（`DualPaneScreen` 里的 `DisposableEffect`）；
   tab chip 只能用 `Color.White.copy(alpha = .14f)` 反色 hack。删掉这条规则，主题系统少一维，状态栏只剩一条规则。
3. **把解释塞进行内**：列表用 10sp 副标题承载时间/权限（手机上几乎不可读）；
   设置用 10sp 段落解释开关（"SHA-256 会把源与目标各完整读一遍…"）。
   这不是"文案多"，是**控件没有能力自己表达状态**。
4. **空态用句子教操作**："点右下角 ＋ 添加 SFTP / FTP / FTPS / WebDAV"、"底部 ＋ 新建，或从对面窗格复制进来"。
   正确做法是给一个可点的行，而不是写说明书。

## 2. Clean 1.0 四条规则

> 这四条是"宪法"。任何新界面先过这四条，再谈配色。

**R1 · 一屏一标题**
标题下面不允许出现解释句、副标题、版本号、口号。需要解释 → 改控件（占位符 / 状态 / 禁用态 / 分组），
或者把解释放进点开才出现的 ⓘ 面板。**列表行内永远不出现说明文字。**

**R2 · 一行一信息**
列表行 = 图标 + 名称（+ 右对齐元数据）。行内不换行、不叠第二行。
行间**没有分割线**，靠 44dp 行高和分组间距分隔；只有分组之间一条 1px 发丝线。

**R3 · 值在行尾**
时间 / 大小 / 当前选项 / 开关，一律右对齐。眼睛沿右侧一列扫，就能比较所有值；
不再出现"文件列表显示：时间"这种把值写进句子里的做法。

**R4 · 颜色只表达状态**
中性灰阶承载层级；强调色只给"选中 / 主操作"；红色只给删除。
文件类型靠**形状**区分，不靠 28dp 彩色底板。主题预设保留，但每套只贡献一个 `primary`。

## 4. 逐屏设计

### 4.1 双列（核心）

```
┌──────────────────────────────────────────┐
│ ☰   内部存储 / Download              ⋮   │  56dp：两条路径，各 26dp
│     SFTP · nas /photo                    │  活动那条 15/600，另一条 12.5 淡色
├──────────────────────────────────────────┤
│ ↑                                        │  36dp，只有图标
│ 📁 Android          │ 📁 2026-11         │  44dp，无逐行分割线
│ 📁 Documents        │ 📁 2026-10         │
│ ▍📁 Pictures        │ 🖼 cover.jpg       │  选中：6% 强调底 + 2dp 左条
│ <> notes.md         │ <> edit.tiff       │
│ 🖼 IMG_2041.jpg     │ 📄 readme.txt      │
│ ...                                      │
├──────────────────────────────────────────┤
│  ‹    ›    ＋    ⇄    ↑                  │  56dp，图标无文字
└──────────────────────────────────────────┘
```

- **顶栏两条路径**：现在只显示活动窗格的路径，另一个窗格在哪完全看不见。两条路径同时显示，
  顺带干掉统计行。点击任一条 = 聚焦该窗格并打开层级菜单。
- **选中态替换路径**：活动那条变成 `已选 3` + 复制/移动/删除三个主操作（其余动作进右侧 ⋮），仍在 26dp 内，不跳高度。
- **过滤态**：路径尾部一枚 20dp 的「过滤 ×」chip，点掉即清除。不再写"· 已过滤"。
- **多标签**：只有 >1 个标签时，顶栏下多一条 28dp 标签条（12sp 名称 + ×）；单标签时零高度。
  标签是功能，不塞进路径行，也不做成"下拉里找" —— 那是把可见状态藏起来。
- **行**：20dp 单色图标 + 15sp 名称。双列不显示时间；单列（≥260dp 窗格）右对齐 12sp 时间。
  权限不再进列表（属性里看），顺带删掉设置里的「时间 / 权限」两档。
- **无逐行分割线**：`PaneView.kt:401` 那行 `DividerPx()` 直接删。这是单行改动、观感提升最大的一处。
- **上一级**：36dp 的 ↑ 图标行，无".."文字。
- **空态**：一行 15sp + 一个按钮（`空文件夹 / 新建`、`无匹配项 / 清除过滤`）。
- **加载**：顶栏下 2dp 进度线 + 活动路径尾部一枚 ×（取消载入）。
  删掉 `#66222222` 全屏遮罩和百分比文字；列表本来就已经 `userScrollEnabled = false`，只需再 gate 住行点击。
- **FAB**：只在剪贴板有内容时出现，40dp 中性底 + 强调色图标；不再用 MT 红。

### 4.2 抽屉（取代首页）

- 头部 56dp：只有 `PanelFM` 17/600。删掉"主题跟随系统"副标题、46dp 白色图标盒、右上 ⋮
  （主题在设置里，添加存储在列表里，⋮ 里的 5 项全是重复入口）。
- 三段：**存储 / 连接 / 工具**。11sp 淡色分组标签，行 44dp，值右对齐（`83 GB 可用` / `SFTP` / `2`）。
- **删掉折叠箭头与 4 个 `expandX` 状态**：卷 2–3 个、工具 6 个，列表短到不需要折叠。少 4 个状态 + 4 个分支。
- **删掉"后台 / 最近"段**：它与书签底部抽屉的「最近」是同一份数据，两处入口只会漂移。
- 空态 = 一行 `＋ 添加存储`，不是一段"右上角 ⋮ → 添加网络存储（SFTP / …）"。
- 长按连接 → 底部动作单（打开 / 编辑 / 断开 / 删除），替代现在带标题+副标题的 AlertDialog。

### 4.3 设置（已落地）

- 9 组：**外观 / 浏览 / 手势 / 文件 / 媒体 / 传输 / 回收站 / 网络 / 关于**。分组标签 11sp 淡色，行 48dp。
- 每行 = 标签 + 当前值 + ›（或开关）。多选（主题 / 配色 / 字体 / 视图 / 副标题 / 缩略图 / 校验 / 并发 / 回收站）
  点开底部 sheet，一行一个单选项；删掉 8 处 `TextButton` 横排 + "xxx：" 前缀。
- 设置页 10 段说明全部删除；User-Agent 与 About 收进对话框，主列表零说明段。
- 原有 **22 个 `prefs.set*` 一个不少**（含 `setListDisplayMode`）；只换布局，不改行为。

### 4.4 工具 / 预览 / 弹窗

- 工具页：标题 + 一个主输入 + 结果区。格式提示进 placeholder（输入即消失），不再有"说明"段落。
- 弹窗：标题 + 一句后果 + 两个按钮。删掉"请选择处理方式："这类半句。
- 权限框：一句"为什么" + 一个按钮。例：
  - `需要「所有文件访问」才能浏览完整存储。` → 去授权
  - `需要「局域网访问」才能连接 NAS / SMB。` → 去授权
- 错误/失败信息**不删**（它们是反馈，不是标语），但统一成一句、不带"请…"的冗余。

## 6. AX：先补语义，再删文案

这是本次改造里最容易被忽略、也最不能省的一步：**现在 0 个 `testTag`，可见文字是唯一的定位手段**。
先删文案再补语义，等于把智能体和 UI 测试一起弄瞎。

顺序反过来：

1. **建 `UiId`**：`object UiId { const val TopBarMenu = "topbar.menu"; … }`，30–40 个常量覆盖主路径。
2. **挂 `Modifier.testTag(UiId.X)`**：主界面所有可点节点（☰ / 两条路径 / ⋮ / 每行 / 底栏 5 个 / 空态按钮 / 开关）。
   根节点同时开 `testTagsAsResourceId = true` —— 否则 `uiautomator dump` 里看不到 testTag，AX 验收是假的。
3. **保留 `contentDescription`**：可见文案砍掉，TalkBack 句子不砍；行的语义里继续带文件名、类型、大小、时间。
4. **统一词表**：现在同一个东西叫「网络存储 / 连接 / 挂载 / 会话」（121 处），
   统一成 **存储 / 连接 / 任务**。智能体按名字找东西时，同义词是灾难。
5. **写 `docs/UI-MAP.md`**：屏幕 → UiId → 动作 → 状态，一页表格。人和智能体读同一份。

额外收益：文案不再是 API。以后改文案不会打断自动化，也不会打断用户肌肉记忆。

## 9. 不做什么 / 待拍板

**不做**：

- 不引入新字体、新设计系统库、navigation-compose；
- 不做 Material 3 Expressive 的大圆角/大色块；

## 10. 每个决定怎么同时提升三端

| 决定 | UX | DX | AX |
|---|---|---|---|
| 删首页 | 少一层导航，启动即双列 | −553 行死代码 | 少一个入口分支 |

| 行单行化 | 名字更大，扫视更快 | 删 `subtitle` 参数 + 2 个纯函数 + 5 条测试 | 每行 1 个文本节点 |
| 值右对齐 | 一列扫完所有值 | 1 个 Row 组件复用 | 语义树扁平、可预测 |
| 说明进 ⓘ | 主列表安静 | 少 33 段文案（估算） | 文案不参与定位 |
| 补 testTag | 无感 | 终于能写 UI 测试 | 智能体可稳定定位 |
