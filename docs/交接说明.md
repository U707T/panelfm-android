## 6. 踩过的坑（务必避免重犯）

### 6.1 加密 ZIP（`ZipCrypto`）——三个真 bug，已修且有回归测试
1. **密钥流是 per-entry 的**，不是全流连续（曾误以为像 RAR 那样跨条目推进 → 第二个条目起全解不开）
2. **必须用裸 deflate**（`Deflater(level, /* nowrap = */ true)`），带 zlib 头会解出 `78 9c` 导致 inflate 失败
3. **`reader` 回调必须写入调用方提供的缓冲区**（早期签名 `() -> Int` 让调用方写自己的缓冲区 → 写侧永远压到全零）
4. 加解密**不是同一个运算**：两者都用「明文」推进密钥，所以 `encrypt`/`decrypt` 分开实现

> 回归测试：`ZipCryptoTest`（与 Python 参考实现逐字节对照）+ `EncryptedZipRoundTripTest`（**用 Python zipfile 交叉验证可被外部工具打开**）

### 6.2 沙箱 / 构建
- Gradle 一律加 `--offline`（网络受限）
- `commons-compress 1.27` **只有加密 ZIP 读侧**（`ZipArchiveInputStream` 的口令参数其实不存在，2 参版本是 encoding），写侧必须自研
- SMBJ 没有 `File.setFileTime`，要用 `setFileInformation(FileBasicInformation(...))`
- SSHD 的 `SftpClient.Attributes` 用 `modifyTime(FileTime)`，不是 `mtime =`
- Kotlin 字符串模板后面紧跟中文要加花括号：`"${verb}并替换"`（`"$verb并替换"` 会被当成变量名 `verb并替换`）

### 6.3 手写补丁的注意点
- 用脚本批量改 Kotlin 时，**务必改完立刻编译**：出现过两次「两行被拼成一行」的静默错误
  （`"open_with" -> ... "clipboard" -> ...`），编译器报错才发现
- 改 `when` 分支 / `data class` 参数时，先 `grep` 所有调用点

## 7. 与 MT 的「不做」边界（保持项目定位）

PanelFM **只做「文件管理 + 预览」**，以下**明确不做**（不要因为「对齐 MT」而加）：
- 逆向：Dex / Arsc / AXML 编辑、签名、加固、混淆对抗、插件系统、MCP
- Root / Shizuku / 注入文件提供器（用 SAF 兜底即可）
- 账号 / VIP / 云备份 / 服务器功能

**注意**：MT **没有回收站**（全 2007 条文案里 0 处），PanelFM 的回收站是**自加能力，要保留**。
