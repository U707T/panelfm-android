## 1. 需求理解与范围界定

### 1.1 一句话定义

> 一个**双窗格**文件管理器：左窗格与右窗格各自独立地浏览「本地 / 压缩包内部 / 任意网络协议」，中间用 `⇄` 完成复制、移动、比较；所有网络协议免费开放；内置文本/图片/音频/字体/压缩包/APK/Hex/文本对比预览；**不含任何逆向工程能力**。

### 1.2 必做（P0）

- 双窗格独立导航：各自路径、前进/后退历史、独立标签页、独立排序/过滤/选择状态。
- 跨窗格操作：复制 / 移动 / 同步路径 / 交换窗格 / 目录差异比较；目标恒为另一窗格当前目录，**不弹目标选择框**。
- 拖拽：拖到另一窗格「目录区域」= 移动，拖到「文件行」= 复制，带高亮/幽灵/落点提示。
- 协议：本地（含 SAF、可选 Root）、FTP、FTPS、SFTP、WebDAV、SMB2/3、S3 兼容对象存储、压缩包只读挂载（zip/7z/tar/APK）。
- 连接管理：分组、书签、快速连接、局域网扫描、导入导出配置。
- 文件操作：新建/重命名/批量重命名/删除+回收站/复制/移动/属性/权限（能拿到时）/校验值/压缩/解压/分享/用系统应用打开。
- 后台任务：进度（字节/百分比/速率/剩余时间）、暂停/继续/取消/重试/全部暂停、冲突策略（覆盖/跳过/保留两者/询问+全部应用）、断点续传。
- 预览：文本编辑器（行号/换行/缩放/编码识别/语法高亮/查找替换/大文件分块）、图片、音频、字体、ZIP/RAR 内部浏览、APK 内部文件浏览、Hex 编辑器、文本对比；未知类型「打开方式」。
- 中文界面 + 明暗主题 + 动态取色；竖屏也保持双列。

### 1.3 可选（P1/P2）

| 功能 | 优先级 | 备注 |
|---|---|---|
| 回收站（本地 + 支持 rename 的协议） | P1 | 删除可撤销 |
| 目录差异对比（含「只复制较新」「镜像」） | P1 | 双窗格天然场景 |
| 局域网扫描（mDNS + TCP 端口扫描 + 协议探测） | P1 | SFTP/FTP/SMB/WebDAV 端口识别 |
| 已安装应用列表 + 导出 APK（不做编辑） | P2 | 复用 APK 内部浏览能力 |
| 文件搜索（本地快搜 / 网络遍历 + 可中断） | P1 | |
| 远程管理（手机起 HTTP/WebDAV 服务，电脑拉取） | P2 | 复用自研 WebDAV/HTTP 层 |
| Root 文件系统（`/data`、`/system` 读写） | P2 | 独立模块，默认关 |
| MCP / 自动化接口 | P2 | 非必需 |
| 平板/折叠屏/外接键鼠的桌面化布局 | P1 | `material3-adaptive` + 快捷键 |
| Windows 版 | 不做 | 原生 Android 单平台，降低维护成本 |

### 1.4 明确不做（与 MT 的边界）

| 不做项 | 说明 |
|---|---|
| APK 反编译、DEX 编辑、Smali 编辑、Arsc 编辑、资源替换、签名重打包、去广告/破解 | **一概不做**，不引入 smali/baksmali、apktool、dexlib 等依赖 |
| DEX 结构解析（类/方法/字段列表）、字符串解密 | 不做；DEX 只允许 **Hex 只读预览** |
| AndroidManifest 反编译为可编辑 XML | 不做；APK 内 `AndroidManifest.xml` 仅 **Hex 原始预览**，另提供**官方 API**（`PackageManager.getPackageArchiveInfo`）显示包名/版本/权限等只读元数据 |
| 账号系统、云同步、会员、授权校验、统计、广告 | 不做 |
| 网络中间人抓包/注入 | 不做 |

> 结论：**文件管理与预览是 100% 范围；逆向是 0%**。任何功能若不慎滑向「修改二进制包」，立即砍掉。

### 1.5 MT 功能 → 本项目映射表（节选）

| MT 能力 | 本项目 | 里程碑 |
|---|---|---|
| 双列 + 底部 `← → ＋ ⇄ ↑` | 同构实现（Compose） | M1 |
| 主页「本地/网络/后台/工具」四段 | 同构 | M1 |
| 网络存储（FTP/WebDAV/SMB/SFTP/S3） | 同构，全部免费 | M2–M6 |
| 后台任务进度条 | 同构（前台服务 + 通知） | M1 / M9 |
| 文本编辑器 / Hex / 图片 / 音频 / 字体 | 同构 | M7 |
| ZIP/APK 内部浏览、解压/压缩 | 同构（做 zip/7z/tar；RAR 只读可选） | M8 |
| APK 编辑 / DEX 反编译 / Arsc | **不做** | — |

### 2.2 分层依赖规则

1. `:feature:*` 只能依赖 `:core:*`，`feature` 之间 **不互相依赖**（跨 feature 需求下沉到 core）。
2. `:core:vfs-api` 不依赖任何协议实现；协议模块只依赖 `vfs-api` + 自己的第三方库。
3. `:core:transfer` 只依赖 `vfs-api`，把「源 VFS 的 Reader」泵到「目标 VFS 的 Writer」，对协议无感知。
4. UI 层**不允许**直接 `import` 任何协议库（OkHttp/commons-net/SMBJ）。
5. 领域层**不允许**引用 `android.content.Context` 的强类型（用 `AppDirs`、`NetworkMonitor` 之类的接口注入），保证纯 JVM 可测。

### 2.3 线程模型

| 工作 | 调度器 | 说明 |
|---|---|---|
| UI 状态组合、格式化 | `Dispatchers.Main.immediate` | 只做纯计算，禁止 IO |
| 本地文件 IO | `Dispatchers.IO` | `FileChannel` / `RandomAccessFile` |
| 网络协议读写 | `vfsDispatcher = Dispatchers.IO.limitedParallelism(32)` | 与本地 IO 隔离，避免大队列拖累 |
| 控制通道（FTP 控制连接、SMB 会话、SFTP channel 建立） | `SessionScope`（**每会话一个单线程 dispatcher**） | FTP 控制命令必须串行；用 `Mutex` 兜底 |
| 图片解码 / 缩略图 | `Dispatchers.Default.limitedParallelism(4)` | 避免抢占 CPU |
| 哈希/校验 | `Dispatchers.Default` | 1MB 分块 + 挂起点 |
| 进度回调节流 | `Flow.sample(200ms)` | UI 只收节流后的值 |

规则：**任何 `suspend` 长任务必须在每个 chunk 前 `ensureActive()`**；取消时走 `try/finally` 清理（关连接、删 `.part`），清理逻辑放 `withContext(NonCancellable)`。

### 2.4 一次「跨窗格复制」的完整数据流

```
用户点 ⇄ → 复制
 └─ DualPaneViewModel.buildCrossPaneRequest()
     ├─ src = 聚焦窗格选中项（无选中 → 当前目录全部）
     ├─ dst = 另一窗格当前路径（实时读取，不弹框）
     ├─ 校验：dst 是目录？同窗格？src 是否包含 dst 自身（防递归复制）？
     ├─ UI：两条路径栏高亮 1.5s + Toast 文案「复制 → smb://nas/media/2026」
     └─ TransferEngine.enqueue(TransferRequest)
         ├─ Planning：递归枚举 src（累计 totalFiles/totalBytes），生成 OperationPlan
         ├─ 快路径：同协议 && 目标支持 serverSideCopy/move → 直接下发，零中转
         ├─ 慢路径：openRead(src) → 缓冲 → openWrite(dst, offset) （跨协议：本地中转管道）
         ├─ 冲突：按 ConflictPolicy 处理；Ask → 任务进入 WaitingConflict，UI 弹窗后 resolve
         └─ 完成：汇总成功/失败，写 task_record，通知栏收尾
```

### 3.2 关键「做不做」边界（避免架构漂移）

- 传输引擎**不做**协议特化分支（`if (scheme == "ftp")`）；协议差异全部通过 `VfsCapabilities` + `Vfs` 接口方法暴露。
- 「服务端快路径」判定放在 `FileOperationPlanner`，不在各协议实现里互相调用。
- UI 不缓存 `FileMetadata`（每次列表给定快照），避免陈旧状态；选择状态存 `Set<VfsUri>`。

## 4. 技术选型与理由

### 4.1 UI 框架决策：Compose 为主 + 两处自绘 View（明确结论）

**结论：Jetpack Compose（Material 3）作为主 UI 框架；文本编辑器与 Hex 视图用自定义 `View` + `AndroidView` 嵌入。**

理由：

1. **双窗格本质是「两棵状态树 + 共享拖拽会话」**。声明式 UI 下 `PaneState` 是唯一样本，窗格间同步（同步按钮、跨窗格高亮、拖拽落点）只是状态派生，View 体系需要大量 `notifyItemChanged` 手工同步，易出 bug。
2. **性能已不是短板**：`LazyColumn` + 稳定 `key` + `contentType` + 不可变数据类（`@Immutable`）+ 预取，1 万条目滚动可达 60/120fps；真机保底用 Macrobenchmark 卡指标，不达标再降级（见风险 R9）。
3. **多形态自适应**：手机竖屏左右双列、平板/折叠自增列、外接显示器，`WindowSizeClass` 一处适配。
4. **单人开发效率**：无 `findViewById`/`ViewHolder`/XML 样板，主题/暗色/动态取色零成本。
5. **两处必须自绘**：
   - `TextEditorView`：几十万行文本需要 `StaticLayout`/按行布局、精确光标、选区、IME、放大缩小、语法高亮增量绘制 —— Compose 文本实现无法满足（且 `BasicTextField` 大文本会 OOM）。
   - `HexView`：固定列网格 + 十六进制/ASCII 双栏 + 偏移跳转，自绘 `Canvas` 最直接。
   两者都通过 `AndroidView(factory = ::TextEditorView)` 嵌入，共享 ViewModel 状态。

## 5. 统一文件抽象层（核心接口定义）

### 5.1 路径模型：URI 风格，全应用唯一标识

```kotlin
/**
 * 统一资源定位：scheme://authority/path?query
 *  examples:
 *    local://emulated/0/Download/a.txt        // 本地（authority 表卷/根标识）
 *    local://saf/A1B2-C3D4/DCIM                // SAF 授权树
 *    ftp://192.168.28.156:21/pub/x.zip
 *    sftp://nas:22/home/u/a.txt
 *    dav://192.168.28.156:5244/dav/media/a.mp4
 *    smb://nas/共享/影片/a.mkv
 *    s3://photos/2026/a.jpg
 *    archive://zip/local%3A%2F%2Femulated%2F0%2Fa.zip!/inner/dir/   // 压缩包内部
 */
@Immutable
data class VfsUri(
    val scheme: String,
    val authority: String,        // host[:port] | 本地卷标识 | bucket
    val path: String,             // 协议原生绝对路径，保证以 '/' 开头（根为 "/"）
    val query: String? = null,
) : Comparable<VfsUri> {
    val name: String get() = path.substringAfterLast('/', "")
    val parent: VfsUri? get() = if (isRoot) null else copy(path = path.substringBeforeLast('/').ifEmpty { "/" })
    val isRoot: Boolean get() = path == "/" || path.isEmpty()
    fun child(childName: String): VfsUri = copy(path = path.trimEnd('/') + "/" + childName)
    override fun toString(): String = "$scheme://$authority$path" + (query?.let { "?$it" } ?: "")

    companion object { fun parse(s: String): VfsUri; fun of(account: ConnectionConfig, path: String): VfsUri }
}
```

约定：
- 路径**永远**用 `/` 分隔（Windows/SMB 侧由实现内部转换）。
- 转义：路径段按 `Uri.encode(segment)` 处理，`archive://` 用 `!/` 分隔内外路径。
- 展示用 `displayPath: String`（不含 scheme/authority 或无密码）与实际 URI 分离。

### 5.3 主接口

```kotlin
interface VirtualFileSystem : AutoCloseable {
    val id: VfsId                      // 稳定标识：连接配置 id 的哈希
    val scheme: String
    val label: String                  // 显示名，如 "NAS-SFTP"
    val capabilities: VfsCapabilities
    val state: StateFlow<VfsState>     // Idle / Connecting / Ready / AuthRequired / Error(msg)

    /** 幂等懒连接；多窗口并发调用只连一次（内部 Mutex） */
    suspend fun connect()

    suspend fun list(uri: VfsUri, options: ListOptions = ListOptions()): ListPage
    /** 流式分页（大目录 / S3 前缀）：UI 边收边渲染，可取消 */
    fun listStream(uri: VfsUri, options: ListOptions): Flow<ListPage>

    suspend fun stat(uri: VfsUri): FileMetadata
    suspend fun exists(uri: VfsUri): Boolean = runCatching { stat(uri) }.isSuccess
    suspend fun mkdir(uri: VfsUri, parents: Boolean = true)
    suspend fun touch(uri: VfsUri)
    suspend fun delete(uris: List<VfsUri>, recursive: Boolean = true, onProgress: ProgressCallback? = null)
    suspend fun rename(from: VfsUri, to: VfsUri): Boolean
    /** 服务端复制；不支持返回 false，由引擎降级为流式泵 */
    suspend fun copy(from: VfsUri, to: VfsUri, recursive: Boolean = true): Boolean
    suspend fun serverSideMove(from: VfsUri, to: VfsUri): Boolean = rename(from, to)

    /** 随机访问读（offset/length 支持则走 Range；不支持则顺序丢弃） */
    fun openRead(uri: VfsUri, offset: Long = 0L, length: Long = -1L): VfsReader
    /** 随机访问写；size 用于预分配/分片；offset>0 表示续传 */
    suspend fun openWrite(
        uri: VfsUri, size: Long?, offset: Long = 0L, contentType: String? = null,
    ): VfsWriter

    suspend fun space(uri: VfsUri): SpaceInfo? = null
    suspend fun checksum(uri: VfsUri, algo: HashAlgo, onProgress: ProgressCallback? = null): String? = null
    suspend fun setPermissions(uri: VfsUri, mode: Int) { throw VfsException.Unsupported("chmod") }
    /** 压缩包/apk 只读挂载；不支持返回 null */
    suspend fun mountArchive(uri: VfsUri): VirtualFileSystem? = null
    override fun close() {}
}

interface VfsReader : AutoCloseable {
    val size: Long?                 // 未知为 null（部分 FTP/SFTP 流）
    val etag: String?
    val lastModified: Long
    val supportsSeek: Boolean
    suspend fun seek(position: Long)                                  // 不支持则 Unsupported
    suspend fun read(buffer: ByteArray, offset: Int = 0, length: Int = buffer.size): Int  // -1 = EOF
    suspend fun readFully(position: Long, length: Int): ByteArray = ...  // 供 Hex/图片解码/媒体 seek
}

interface VfsWriter : AutoCloseable {
    val writtenBytes: Long
    /** 续传能力：MULTIPART 时返回已上传分片；UI 显示「已续传 xx%」 */
    val resumability: Resumability
    suspend fun write(buffer: ByteArray, offset: Int, length: Int)
    suspend fun flush()
    suspend fun commit()      // 本地：临时文件原子改名；S3：CompleteMultipartUpload；DAV：MOVE 合并
    suspend fun abort()       // 尽力清理（删 .part / AbortMultipartUpload）
}

@Immutable data class ListOptions(
    val sort: SortSpec = SortSpec(SortBy.NAME, ascending = true, dirsFirst = true),
    val showHidden: Boolean = false,
    val filter: String? = null,
    val page: Page? = null,          // null = 全量
)
@Immutable data class ListPage(val items: List<FileMetadata>, val nextToken: String? = null)
@Immutable data class SpaceInfo(val total: Long, val free: Long, val used: Long? = null)
```

### 6.2 窗格独立性与历史栈规则

- 导航（`navigate(uri)`）：把当前 `location` 压入 `back`，清空 `forward`；`back` 上限 100 条，去重（同 URI 连续不重复压栈）。
- 后退 / 前进：在 `back`/`forward` 之间搬移 `PaneLocation`（含 `scrollIndex` → 恢复滚动位置与选择集）。
- 切标签页：每个 tab 独立持有一套栈；`＋` 新建 tab 默认继承当前 tab 的 VFS + 根路径（MT 语义：便于对比同存储不同目录）。
- 跨窗格不同 VFS：完全允许（左 = `local://emulated/0`，右 = `s3://photos`）。
- 焦点态：`focused` 决定 `← → ＋ ⇄ ↑` 与主页点击的目标窗格；聚焦窗格标题栏描边高亮。

### 6.3 同步按钮（⇄ 菜单 → 「同步路径」）

规则（严格按需求）：

```
syncPath(from = focused, to = other):
  if from.uri 在压缩包内部：                       // archive://zip/local%3A%2F%2F..a.zip!/x/y
      other.navigate(dirOf(archive 文件本身))       // 另一窗格跳到压缩包所在位置（同级目录）
  else if from.uri 是目录：
      other.navigate(尽量等价路径)                  // 见下「跨协议路径等价」
  else if from.uri 是文件：
      other.navigate(from.uri.parent)              // 跳到文件所在目录，并高亮该文件（可选）

跨协议路径等价（尽力而为，失败给出友好提示 + 一键「复制整个路径」）：
  1) 同协议：直接取同一路径。
  2) local ↔ 网络：尝试匹配「基础路径」映射（连接配置里可设 basePath ↔ localBasePath 映射表）；
     无映射则提示「目标协议无法定位该路径」并提供「在目标窗格打开其根目录」。
```

补充同步项（复选框，记住上次选择）：① 排序方式；② 显示隐藏文件；③ 视图（列表/网格）。

### 6.4 跨窗格操作（核心体验）

- 触发：命令栏 `⇄` → 菜单「复制到对面 / 移动到对面 / 同步路径 / 交换窗格 / 比较目录」；或长按拖拽。
- 源：聚焦窗格的选中项；**无选中 = 当前目录全部可见项**（含「仅复制选中」开关）。
- 目标：**另一窗格当前目录（实时取值，不弹目标选择框）**。
- 执行前的可见反馈（必须）：
  1. 两个窗格路径栏同时高亮（左侧源路径 + 右侧目标路径），持续 1.5–2s；
  2. 中央浮层文案：`复制 12 项（248 MB） → smb://nas/media/2026`；
  3. 目标窗格列表顶部插入一条「即将落地」的幽灵行（灰显 + 闪烁），落地后替换为真实项。
- 移动的二次确认：弹确认框，展示
  `移动 12 项 / 总计 248 MB / 目标：smb://nas/media/2026 / 跨协议：需要下载后上传（先删源）`
  + 复选框「本次会话不再询问」（同源同目标时复用）。
- 危险检查（前置拦截）：目标在源内部（递归自复制）、目标协议只读、目标空间不足（能拿到 `SpaceInfo` 时预警）、路径深度/名称非法（NTFS 保留字符）。
- 服务端快路径：同 VFS 且 `rename=true` → 移动直接 `rename`；同 VFS 且 `serverSideCopy=true` → 复制走服务端；跨 VFS 一律本地中转（见 §8.4）。

### 6.5 拖拽（手势 + 系统 DnD 双通道）

**实现方式：自研拖拽层（Compose 手势 + 全屏 `DragOverlay`），同时注册系统 `DragAndDropTarget` 用于接收外部应用文件。**

- 长按 300ms 进入拖拽（`pointerInput { detectDragGesturesAfterLongPress }`），若已有多选则整组拖拽；未多选则拖拽单项。
- `DragSession` 全局状态：`items: List<VfsUri>`、`current: Offset`、`hoverTarget: DropTarget?`。
- 落点判定（按需求）：命中另一窗格的**列表项行区域** → `COPY`；命中**目录区背景/顶部面包屑/空白区** → `MOVE`；命中同窗格 → 仅排序/无效（显示禁止图标）。
- 视觉反馈：
  - 拖拽幽灵：半透明卡片 + 数量角标 `×12`；
  - 落点窗格整块描边（复制=蓝 `#3B82F6`，移动=橙 `#F59E0B`）；
  - 顶部横幅：「松手：复制到 `/media/2026`」/「松手：移动到 …」；
  - 目标行（若是目录行）加 `目标` 徽标；
  - 无效落点：红色禁止 + 抖动（haptic）。
- 边缘自动滚动：拖到窗格上下边缘 48dp 内，按 8dp/帧滚动；跨窗格长距离拖拽时允许滚动**任一端**。
- 松手后：复制直接执行；移动弹二次确认（与 §6.4 一致）。
- 外部拖入（从别的 App 拖文件进来）：系统 `DragAndDropTarget` 收 `ClipData` → 转 `content://` → `ContentResolverVfs` 只读源 → 落到窗格当前目录。

### 6.6 支持场景与「网络↔网络」

| 场景 | 路径 | 说明 |
|---|---|---|
| 本地 ↔ 网络 | 流式泵（本地临时文件可选） | 大文件默认「边下边传」，不落盘；网络差时自动落盘续传 |
| 压缩包 ↔ 本地 | `ArchiveVfs` 读 → 本地写 | 支持「只解压选中项」；归档写入 = 压缩 |
| 网络 ↔ 网络 | 本地中转（内存管道 + 可选磁盘 spool） | 同一会话共享同一条「读流 → 写流」泵，无二次落盘 |
| 网络 ↔ 网络（同协议同服务端） | 服务端 COPY/MOVE（WebDAV、S3 CopyObject、FTP RNFR/RNTO） | 秒级完成，显示「服务端完成」徽标 |
| 目录差异对比 | `FolderCompareEngine` | 见 §6.7 |
| 两个窗格挂不同网络存储 | 天然支持 | 各自 `VfsLease`，互不影响，会话独立 |

中转细节：`RelayPipe` 默认 4 MB 环形缓冲（背压天然生效：读慢则写阻塞）；当「源快目标慢」且文件 > 64 MB 时切到磁盘 spool（`cacheDir/relay/<taskId>/<index>.part`），保证可暂停/续传。

### 6.7 目录差异对比（双窗格专属）

## 7. 网络协议抽象层与各协议实现要点

### 7.1 抽象层职责

协议模块只做三件事：**（a）连接与认证；（b）把协议原语翻译成 `Vfs` 方法；（c）如实声明能力位**。所有「快路径/慢路径」「续传/重传」「进度节流」都在引擎层，不在协议层。

```kotlin
abstract class BaseVfs(protected val env: VfsEnv) : VirtualFileSystem {
    protected val sessionScope = CoroutineScope(SupervisorJob() + env.dispatchers.session(id))  // 单线程
    protected val controlMutex = Mutex()          // FTP 控制连接 / SMB 会话 串行化
    override val state = MutableStateFlow<VfsState>(VfsState.Idle)
    protected suspend fun <T> withRetry(times: Int = 3, block: suspend () -> T): T = ...
}
```

### 7.2 各协议实现要点

#### 7.2.1 FTP / FTPS（`commons-net`）

- 传输模式：默认 `PASV`，`EPSV with IPv4 = true`；`ACTIVE` 可切换（Android 上监听本地端口可行）；编码 `UTF-8`（失败回退 `GBK`，检测服务器 `OPTS UTF8 ON`）。
- 目录列举：优先 `MLSD`（机器可读 + 精确 mtime），失败回退 `LIST` 自研解析器（支持 UNIX `ls -l`、Windows IIS、MLSD 三种格式，已按 Flutter 版实现移植）。
- 续传：下载 `REST offset` + `RETR`；上传 `REST offset` + `APPE`/`STOR`（服务器支持 `REST STREAM` 时）。
- 认证：匿名 / 用户名密码；`ACCT`；`CCC`（清空控制通道 TLS，可选）。
- FTPS：显式 `AUTH TLS`（21）与隐式（990）；`PBSZ 0` + `PROT P`（数据通道加密）；`PROT C` 可切换；自签证书策略：连接级「信任此证书」→ 存 SHA-256 指纹到 `known_hosts`。
- 稳定性：`NOOP` 心跳（每 30s，仅空闲时）；控制命令超时 20s，数据连接超时 60s；`TYPE I` 二进制；主动模式防火墙提示文案。
- 校验：`SIZE`/`MDTM`；`MDTM` 时区解析（服务器常返回 UTC，需按 `YYYYMMDDHHMMSS` 解析）。

#### 7.2.2 SFTP（Apache MINA SSHD）

- 认证：密码；公钥（`OpenSSH`/`PuTTY .ppk` 导入，支持加密私钥口令；`ed25519`/`ecdsa`/`rsa`）；`keyboard-interactive` 兜底。
- 算法：显式开启 `chacha20-poly1305@openssh.com`、`aes256-gcm@openssh.com`、`curve25519-sha256`、`ssh-ed25519`（**这正是选 MINA 的原因：内置实现，无需 BouncyCastle**）。
- 跳板机（ProxyJump）：先用 `SshClient` 连接堡垒机 → `direct-tcpip` 通道建立到目标主机的 TCP → 第二个 `SshClient` 会话跑在隧道上（支持多级链 `A→B→C`）。
- 主机指纹：TOFU（首次信任并记录到 `known_hosts` 表），变化时阻止连接并提示中间人风险。
- 操作映射：`list` → `SFTPClient.readDir`（含 `.` `..` 过滤；`longname` 解析兜底权限/owner）；`rename` → `rename`（同分区）；`copy` → 服务端无原生复制 → **返回 false**（引擎降级流式）；`openRead(offset)` → `open(path, READ)` + `seek`；`openWrite(offset)` → `open(path, WRITE|CREATE)` + `seek`（续传）；`chmod` → `setPermissions`。
- 符号链接：`readLink` 暴露 target，默认不跟随（避免环路），提供「跟随符号链接」选项。
- 局域网 IP 扫描（`LanScanner`）：枚举网段（`/24`，从 `NetworkInterface` 取本机 IP）+ 可选手工范围；并发 64，端口 `22` TCP 握手 400ms 超时；命中后读 banner（`SSH-2.0-*`）确认；再尝试匿名/已知凭据的 `none` 认证探测是否需要账号。同时支持 mDNS（`_sftp-ssh._tcp`）与 SSDP。

#### 7.2.3 WebDAV（自研 `DavClient` on OkHttp）

- 方法：`PROPFIND Depth: 0/1`（`allprop` + 显式属性集，兼容不返回 `getlastmodified` 的服务器）、`MKCOL`（递归建目录自实现）、`GET`（`Range`）、`PUT`（`Content-Length`/流式/`Content-Range` 续传）、`DELETE`、`MOVE`/`COPY`（`Overwrite: T/F`）、`LOCK`（可选，仅当服务器强制）。
- XML：`XmlPullParser` 流式解析 `207 Multi-Status`，命名空间 `D:`/`lp1:` 通吃；`href` 做百分号解码 + 相对路径归一化（Alist/Nextcloud 差异点）；`getcontentlength` 缺失时用 `GET Range: bytes=0-0` 探测大小（懒探测，仅详情页触发）。
- **重定向（307/308）**：OkHttp 的 `followRedirects` 会改写方法，因此自研 `RedirectInterceptor`：仅对 `301/302/303` 做 `GET` 降级，`307/308` 时**保持原方法 + 保留请求体**（body 需可重放：`openWrite` 的流式体用「先落临时文件再重放」或 `RequestBody` 可重放实现）；限制跳转次数 10，跨主机跳转时剥掉 `Authorization`（防凭据泄露），仅当目标与源同主机或用户显式允许「跨域跟随」时才带。
- 认证：`Basic`（默认）、`Digest`（OkHttp 需自研，按需）、`Bearer`（Alist token）；`Authorization` 只在同源跳转保留。
- **自定义 User-Agent**：设置项 + 每连接覆盖（部分网盘按 UA 走不同后端）。
- **信任自签证书**：连接级开关 → 为该 host 构造专用 `SSLSocketFactory`（`TrustManager` 校验指纹），不动全局默认。
- PUT 落点策略：目标同目录 `.panelfm.part-<uuid>` → `MOVE` 到最终名（原子性最好的服务器），不支持则直接 PUT 覆盖 + 失败回滚。
- 服务端快路径：`COPY`/`MOVE` + `Overwrite` 头 → `serverSideCopy=true, rename=true`。

#### 7.2.4 SMB2/3（SMBJ，备选 jcifs-ng）

- 协商：SMB `3.1.1 → 3.0.2 → 2.1`（不用 SMB1），`signing` 按服务器要求自动；SMB3 加密（AES-GCM/CCM）在支持时启用。
- 认证：NTLMv2（域/工作组，`DOMAIN\user` 或 `user@domain`）；Kerberos 不做（无 KDC 场景）。
- 共享枚举：`NetShareEnum` 列出可访问共享（需权限）；否则手工填共享名。
- 路径：`smb://host/share/dir/file`，UNC 保留字符（`:` `*` `?` `"` `<` `>` `|`）在新建时校验并提示。
- 目录列举：`Directory.query()` 取 `FileIdBothDirectoryInformation`（含 mtime/size/attributes），过滤 `System`/`Hidden` 按开关。
- **流媒体播放**：`SmbRandomAccessFile` 风格随机读（SMBJ `File.read` with `offset`）→ `VfsReader.readFully` → 交给 `VfsDataSource`（Media3）按 1 MB 预取 + 8 MB 窗口缓存；播放器 seek 只触发一次 SMB read。
- 续传：支持按偏移写（`.part` 文件 + `setLength`/seek），`rangeWrite=true`。
- 风险与退路：SMBJ 需要 `jna`（NDFS 解析）；Android 上若 `jna` 加载异常，则 `java.library.path` 缺失 → 用「禁 DFS + 自定义 `DfsResolver`」绕过；仍不行则切 `jcifs-ng`（LGPL，纯 socket，实测可用）——**实现一个 `SmbBackend` 接口，两套实现可切换**。

#### 7.2.5 S3 兼容对象存储（minio-java / 自研 SigV4）

- 认证：`SigV4`（`AK/SK`，Session Token 可选）；区域自动探测（先 `us-east-1`，`AuthorizationHeaderMalformed` 响应里读正确 region 后重试）。
- 地址风格：**路径样式**默认（`http://host:port/bucket/key`），虚拟主机样式可选（供 AWS/R2 等）；`endpoint` 自定义 + 「在线协议 http/https」（自建 MinIO/Alist 常用 http）。
- **自定义下载域名**：配置 `downloadDomain`（如 CDN 域名/公网域名），`GET`/播放/缩略图走该域名；可选签名 URL（`presignedGet`，过期时间可设）用于外链。
- 列举：`ListBuckets`（**一键加载 Bucket 列表**，UI 直接给下拉选择）→ 选 bucket 后惰性 `ListObjectsV2`（`delimiter="/"` 模拟目录，`continuation-token` 分页，`listStream` 流式渲染）。
- 写入：≤64 MB 单次 `PutObject`；>64 MB 或未知大小 → **分段上传**（默认 8 MB part，`uploadId` + 分片 ETag 落库，可跨进程续传）；**自动 Content-Type**：按扩展名映射表 + 可选 `mime.types` 覆盖；同时设置 `Cache-Control`（图片/视频长缓存）。
- 复制/移动：服务端 `CopyObject`（同 bucket 秒级；跨 bucket 亦可），移动 = `CopyObject` + `DeleteObject`（无原生 move）。
- 兼容性备注：R2（无 `ListBuckets` 需手填 bucket、无 Storage Class）、COS（`ListBuckets` 需权限、默认 path-style ok）、MinIO（全功能）、七牛/B2（部分 `x-amz-*` 扩展缺失 → 能力位自动降级）。
- 校验：`ETag`（单段=MD5；分段=`<md5>-<n>`，不能当整体 MD5 用）→ 校验值功能优先 `x-amz-checksum-crc32/sha256`。

#### 7.2.6 本地 / SAF / Root

- `LocalVfs`：`File`/`NIO`（`Files.readAttributes` 拿 POSIX 权限）；容量 `StatFs`；`/storage/emulated/0` 通过 `MANAGE_EXTERNAL_STORAGE` 直读；隐藏文件按 `.` 前缀。
- `SafVfs`：`DocumentsContract` 树 URI 映射成虚拟路径（`local://saf/<treeId>/...`），支持 `Android/data`、`Android/obb`、外置 SD 卡；写操作注意 SAF 限制（无 rename 跨目录、无 mtime 设置）→ 能力位如实声明；`SAF` 的 `openRead` 用 `ParcelFileDescriptor` + `FileInputStream`（可 seek 时用 `FileChannel`）。
- `RootVfs`（可选）：`libsu`，`/data`、`/system`；`ls`/`stat` 用 `toybox` 输出解析，`cat`/`dd` 做读写，`chmod`/`chown` 直通；默认关闭，设置里显式开启。
- `ContentVfs`：`content://` 只读源（用于接收外部分享/拖入的文件）+ 写入（`MediaStore` 保存到相册）。

## 8. 连接池、会话管理、断点续传、缩略图缓存

### 8.1 会话复用（同一网络配置被两个窗格/多个任务引用）

- `VfsRegistry.acquire(accountId)` 返回 `VfsLease`（引用计数）；**实例级唯一**：`Map<AccountKey, VfsHolder>`，`AccountKey = hash(type, host, port, user, basePath, options)`（同一账号在同一 App 内共享连接，不同 App 实例不共享）。
- 空闲回收：引用计数为 0 且空闲 > 5 分钟 → `close()`；有运行中任务时置 pin（不回收）。
- 单协议并发：FTP 控制连接串行（`controlMutex` + 数据连接独立）；SFTP 允许多 channel（>1 时可以横向扩并发）；SMB 每 share 一个 session，句柄池上限 16；WebDAV/S3 共享 `OkHttpClient`（`ConnectionPool(maxIdle=8, keepAlive=5min)`，`Dispatcher.maxRequestsPerHost=12`）。

### 8.2 传输引擎

```kotlin
class TransferEngine(
    private val registry: VfsRegistry,
    private val planner: FileOperationPlanner,
    private val resume: ResumeDao,
    private val prefs: PrefsStore,
    private val scope: CoroutineScope,
) {
    val tasks: StateFlow<List<TransferSnapshot>>
    fun enqueue(request: TransferRequest): TaskId
    suspend fun pause(id: TaskId); suspend fun resume(id: TaskId)
    suspend fun cancel(id: TaskId); suspend fun retryFailed(id: TaskId)
    suspend fun pauseAll(); suspend fun resumeAll()
}

@Immutable data class TransferRequest(
    val sources: List<VfsUri>,
    val destDir: VfsUri,
    val op: TransferOp,                     // COPY, MOVE, EXTRACT, COMPRESS, UPLOAD, DELETE
    val conflict: ConflictPolicy = ConflictPolicy.ASK,
    val verify: VerifyMode = VerifyMode.NONE,   // NONE / SIZE / HASH
    val archive: ArchiveOptions? = null,
)

sealed interface TaskState {
    data object Queued : TaskState
    data class Planning(val scanned: Int, val bytes: Long) : TaskState
    data class Running(val current: VfsUri, val index: Int, val total: Int, val bytes: Long, val totalBytes: Long, val speedBps: Long) : TaskState
    data object Paused : TaskState
    data class WaitingConflict(val conflict: ConflictInfo) : TaskState
    data class Done(val ok: Int, val failed: List<FailedItem>, val bytes: Long, val elapsedMs: Long) : TaskState
    data class Failed(val error: VfsException) : TaskState
    data object Cancelled : TaskState
}
```

流水线：

```
plan → [每项]
   ├ 目录: mkdir（保证父目录）
   ├ 文件:
   │   ├ 冲突判定 → 覆盖/跳过/保留两者/询问
   │   ├ 快路径: 同VFS && (rename|serverSideCopy) → 直接下发
   │   └ 慢路径: 
   │        src.openRead(uri, offset=resumeOffset) 
   │        → [gate.checkpoint() 每 256KB] 
   │        → dst.openWrite(uri, size, offset=resumeOffset) 
   │        → 写、报进度（节流 200ms）、可取消
   ├ MOVE 收尾: 传输成功后 delete(src)（失败则标记「已复制未删除」，可重试删除）
   └ 失败: 记录 error + 可「只重试失败项」
```

- 并发：任务级并发 `maxConcurrentTasks`（默认 2，可 1–4）；单任务内单文件串行（稳定、可预期）；同一任务的多文件可选的「小文件并行 3 路」（< 1 MB 的文件）。
- 暂停闸门：`TransferGate`（`suspend fun checkpoint()`），暂停 → 挂起；取消 → 抛 `VfsException.Cancelled`；取消/异常清理在 `NonCancellable` 中执行。
- 冲突策略：`OVERWRITE / SKIP / KEEP_BOTH(name (1).ext) / ASK(+applyAll)`；覆盖时若为目录则递归；保留两者支持 `name (n)` 与 `name-YYYYMMDD-HHmmss` 两种风格（设置可切）。
- 校验：默认 `SIZE`（完成即比对大小），可选 `HASH`（源与目标都算 MD5/SHA-256，慢，仅对重要数据）。
- 完成通知：前台服务通知栏进度 + 完成/失败汇总；`task_record` 落库（历史可查）。

### 8.3 断点续传（分层实现）

| 协议 | 上传续传 | 下载续传 | 校验符 |
|---|---|---|---|
| local | 偏移写（`.part` + `renameTo`） | 偏移读 | size + mtime |
| saf | 不支持偏移写 → 重传 | 偏移读（可 seek 时） | size |
| ftp/ftps | `REST offset` + `STOR`（服务器不支持 → 重传） | `REST offset` + `RETR` | size（可选 `MDTM`） |
| sftp | `open(WRITE)` + `seek(offset)` | `open(READ)` + `seek(offset)` | size |
| webdav | 分片 PUT 到 `.part-<uuid>` → `MOVE` 合并（或服务器 chunked 上传 API，如 Nextcloud `/uploads/`） | `GET` + `Range` | `ETag`/`Last-Modified` |
| smb | `File.seek` + 写 | `File.read(offset)` | size + mtime |
| s3 | **Multipart Upload**：`uploadId` + 已上传 part 列表落库；重连后 `ListParts` 核对 | `Range` GET | `ETag` + size |

`resume_entry` 表结构（关键字段）：
```
id, task_id, item_index, src_uri, dst_uri, dst_temp_uri, offset_done, total_size,
validator_etag, validator_mtime, part_size, upload_id, updated_at, state(NEW/UPLOADING/DONE/FAILED)
```
续传前置校验（**必须**，否则宁可重传）：
1. 目标存在且是同一临时文件/incomplete upload；
2. `总大小` 一致；
3. 校验符一致（`ETag`/`mtime`/`size`）；
4. 已写偏移 ≤ 总量。
任一不符 → 删除临时件 → 从 0 重传，并在任务 UI 标注「不支持续传，已重传」。

### 8.4 网络↔网络中转

```
Task: A(sftp) → B(s3)
  └ 计划：可流式 → 建 1 个 pump：
      a = A.openRead(uriA)            // 64KB/次
      b = B.openWrite(uriB, size, 0)  // S3 = 一次 multipart（8MB 分片，天然续传）
      loop { n = a.read(buf); 如果 S3 分片满 → 提交分片（进度 + 断点） ; b.write(buf, 0, n) ; gate.checkpoint() }
      b.commit(); a.close()
  └ 若源慢/目标抖：切 spool 模式（磁盘缓存 .part，可暂停/跨进程续传）
  └ 同协议快路径：WebDAV COPY、S3 CopyObject、FTP RNFR/RNTO 直连
```

### 8.5 缩略图缓存策略

- 三级缓存：
  1. 内存：Coil `MemoryCache`（按屏幕尺寸和「当前目录项数」动态上限，默认 32 MB）；
  2. 磁盘：`cacheDir/thumbs/<vfsIdHash>/<sha1(path)>-<w>x<h>.webp`（Coil `DiskCache`），LRU 上限 256 MB（可设）；
  3. 远程元数据索引（Room `thumb_index`）：记录 `path/size/mtime/etag → 文件是否存在`，用于「远程文件变了 → 失效重取」。
- 触发条件（每条可配）：
  | 协议 | 默认 | 备注 |
  |---|---|---|
  | local | 开（图片/视频/APK 图标） | 本地即时 |
  | webdav/smb/sftp/ftp（局域网） | 开 | 单张限制 ≤ 2 MB，超出跳过 |
  | s3 | 开（走可能计费的下载） | 默认「仅 Wi-Fi」+「按需」 |
  | 移动数据 | 关（可开） | 设置项：「仅 Wi-Fi 加载缩略图」 |
- **快速滚动跳过**：`isFastScrolling = listState.isScrollInProgress && abs(velocity) > threshold`；快速滚动期间不发起新请求，仅显示扩展名图标；停止滚动 200ms 后按可视区优先队列（顶部优先）补图。
- 并发与背压：全局 `Semaphore(4)`；同一 path 去重（Coil 自带 request 去重）；缩略图请求优先级低于传输任务（大任务运行时降到 2）。
- 失效：mtime/size/etag 变化、目标目录重新列出、用户手动「清除缩略图缓存」。
- 失败与降级：连续失败 ≥3 的 host 进入「缩略图熔断」（5 分钟内不再请求）。

### 8.6 后台与前台服务

- 传输任务运行时启动前台服务（类型 `dataSync`），通知显示：总进度、当前文件、速率、暂停/全部暂停按钮。
- Android 15/16+ 对 `dataSync` FGS 有时长上限（累计 6h/24h）→ 对策：超时前自动降级为「应用内继续（须保持前台）」或建议用户分批；同时保证**任务随时可续传**，即使服务被杀。
- 进程策略：单进程（`:app`），传输跑在 `TransferEngine`（应用级 `CoroutineScope(SupervisorJob + Dispatchers.IO)`），前台服务只做保活与通知。理由：会话可复用、无 IPC 复杂度、崩溃恢复靠 `resume_entry` 持久化。
- 屏幕/网络：传输期间持有 `WakeLock(PARTIAL_WAKE_LOCK)` + `WifiLock`（不选 `FULL_WAKE_LOCK`）；网络从 Wi-Fi 切到蜂窝时按设置暂停（默认暂停，避免流量）。

## 9. 预览模块设计

### 9.1 预览调度中心

```kotlin
interface PreviewHandler {
    val id: String
    /** 返回优先级，0 = 不处理；值大者优先 */
    fun canHandle(ctx: PreviewContext): Int
    @Composable fun Content(vm: PreviewViewModel, ctx: PreviewContext)
}

@Immutable data class PreviewContext(
    val uri: VfsUri, val meta: FileMetadata, val vfs: VirtualFileSystem,
    val mode: PreviewMode,                 // VIEW / EDIT / FORCE_AS
    val forceAs: ForceOpenType? = null,    // TEXT / HEX / IMAGE / ARCHIVE
    val host: PaneSide? = null,
)

class PreviewRouter @Inject constructor(
    private val handlers: Set<PreviewHandler>,      // Hilt multibinding
) {
    fun resolve(ctx: PreviewContext): PreviewHandler
}
```

分派规则（按优先级）：

1. `forceAs`（用户「以文本打开 / 以 Hex 打开 / 以压缩包打开 / 以图片打开」）→ 直接命中；
2. 压缩包扩展名（zip/7z/tar/gz/jar/apk/rar）→ Archive/APK handler；
3. MIME 精确匹配（`image/*`、`audio/*`、`video/*`、`font/*`、`text/*`、`application/pdf`）；
4. 扩展名表（`.txt .log .md .json .xml .ini .properties .kt .java .js .html .css .sh .conf .yml` → 文本；`.ttf .otf .ttc .woff` → 字体；`.bin .dat .so .dex .db` → Hex）；
5. 启发式：文件 < 1 MB 且前 4KB 是合法 UTF-8 且无 NUL → 文本；其余 → Hex；
6. 都不中 → **「打开方式」**：内部预览器列表 + 系统 `Intent.createChooser` + 「复制路径」「分享」。
7. 无预览器（如 `.docx`）也提供「Hex 查看」「属性」。

调度中心的附加职责：记住「扩展名 → 上次选择的预览器」（Room `open_with_pref`）；「总是用这个打开」；预览历史（最近 50 条）。

### 9.2 各类型预览实现要点

#### 9.2.1 文本编辑器（`TextEditorView`，自绘 View）

- 模型：`PieceTable`（初始缓冲区 + 增量缓冲区）承载编辑；对大文件提供**只读模式**。
- 布局：`StaticLayout` 按行布局 + 虚拟滚动；行号栏独立绘制；光标/选区自绘 + `InputConnection`（IME 走 `BaseInputConnection`）。
- 大文件分块加载：
  - 文件 > 2 MB 或 > 50 万行 → 进入 `WindowedTextSource`：内存只保留屏幕前后各 200 行；行偏移索引用「稀疏索引」（每 1024 行记一个字节偏移，缺失部分按需扫描），索引在后台线程增量建立并显示进度；
  - 编辑仅允许在已加载窗口；保存时整文件重写（临时文件 + 原子改名）。
- 编码识别：BOM（UTF-8/16/32）→ `android.icu.text.CharsetDetector`（Android 自带 ICU，支持 GBK/GB18030/Big5/Shift_JIS）→ 回退 UTF-8；顶部显示并可**手动切换编码重载/另存**。
- 换行：LF/CRLF/CR 检测与切换（保存时按偏好写回）。
- 功能：行号、自动换行开关、字号 8–32sp（双指缩放 + 设置记忆）、查找/替换（支持正则、区分大小写、全词、循环查找、替换全部带撤销）、跳转行、语法高亮（内置 JSON/XML/INI/Properties/SH/Kotlin/Java/JS/HTML/CSS/Markdown/Python/YAML，`SyntaxLexer` 增量词法，仅对可视区高亮）。
- 保存保留权限：本地文件 → 记录原 `posixPermissions`/`owner`/`mtime` → 写临时文件 → `Files.move(ATOMIC_MOVE)` → `Os.chmod`/`Os.chown`（chown 需 root，否则跳过）恢复；SAF → 用 `ParcelFileDescriptor` 原地覆盖（`"rwt"` 模式）尽力保留。
- 只读保护：网络协议无写权限 / 文件 > 阈值 / 二进制判定 → 顶部提示「只读」。

#### 9.2.2 图片

- 解码：`ImageDecoder`（API 28+）/ `BitmapFactory` + `inSampleSize`，目标 = 屏幕尺寸 × DPR，避免 OOM；超长图（> 8k px）分块渲染。
- 交互：手势缩放（`detectTransformGestures`）、双击缩放、平移、旋转/镜像、适应宽度、EXIF 信息（`ExifInterface`）、设为壁纸、分享、左右切换同目录图片（预加载相邻 1 张）。
- 支持 GIF/WebP 动图（Coil 的 animated 支持）、HDR/HEIC（`ImageDecoder` 原生）、SVG（可选，走 `androidsvg`，Apache-2.0）。
- 远程：`openRead` 流式 + 先取头部（Range）判断尺寸；大图先显示低清（缩略图）再替换高清明细。

#### 9.2.3 音频 / 视频

- Media3 `ExoPlayer` + `VfsDataSource`（自定义 `DataSource.Factory`，scheme → VFS）：

```kotlin
class VfsDataSource(private val factory: VfsRegistry) : DataSource {
    override fun open(dataSpec: DataSpec): Long { /* 建立 VfsReader, seek(dataSpec.position) */ }
    override fun read(buf: ByteArray, off: Int, len: Int): Int  // 直读 VFS
    override fun getUri(): Uri
}
```
- 缓存：`SimpleCache`（LRU 1 GB，可设）→ 网络视频回看与拖动不重复下载；播放 SMB/WebDAV 局域网视频依赖 `rangeRead`（SMB 分块预取、DAV Range、SFTP seek）。
- 音频：后台播放（MediaSession + 通知栏控制）、播放列表（当前目录音频）、倍速/循环/随机、ID3/`MediaMetadataRetriever` 元数据。
- 视频：全屏、手势调亮度/音量/进度、画中画（`PictureInPictureParams`）、字幕外挂（同目录同名 `.srt/.ass` 自动加载）。
- 兜底：不支持的编码 → 「用系统播放器打开」（`Intent.ACTION_VIEW`，`content://` 或 `file://`）。

#### 9.2.4 字体预览

- 元数据：自研 sfnt 解析（`name` 表取 family/subfamily/version/copyright，`head`/`hhea`/`OS/2` 取设计者信息，`cmap` 统计字符覆盖率）；可选 `fontbox` 交叉验证。
- 预览区：
  1. 顶部信息卡（字体名、版本、字符数、支持语言）；
  2. 采样文本可编辑，多字号（12/16/24/48）联动；
  3. 字形网格（`Canvas` 绘制 `Typeface` 的 BMP 区 & 补充平面抽样，支持「显示全部 65536 个码位」分页）；
  4. 变体（`Typeface.Builder` 多 weight）与 fallback 提示。
- 对应：TTC 集合给出子字体列表选择。

#### 9.2.5 压缩包内部浏览（ZIP / RAR / 7z / TAR / APK）

- `ArchiveVfs` 把压缩包**挂载成只读 VFS**（`archive://zip/<encoded:archive-uri>!/inner/path`），因此：
  - 双窗格可直接进入压缩包内部并与本地/网络互传（需求 §6.6 场景）；
  - 预览系统对内层文件零改动（内层文本/图片/Hex 直接用同一套 handler）。
- 实现：zip 用 `ZipFile`（随机访问，`central directory` 定位）；7z 用 `commons-compress SevenZFile`（注：7z 无随机索引 → 顺序读 + 索引缓存）；tar.gz 顺序解压 + 索引；rar 用 `junrar`（只读，可整体解开到临时目录做随机访问）。
- 展示：列表（名称/大小/压缩后大小/时间/CRC）+ 排序 + 搜索（内层）+ 属性；单个条目可「预览、解压到当前目录、解压到对面窗格」（走传输引擎，进度可见）。
- 写（压缩）：`compress` 支持 zip/7z/tar.gz（commons-compress，流式写 + 进度），可选分卷/密码（zip AES）；RAR 只读（许可原因）。
- 编码：内层文件名 GBK/CP437 乱码处理 → 尝试 UTF-8 → GBK → `zip -E` 标志判断（`ZipArchiveEntry` 的 `extra field` / general purpose bit 11）。

#### 9.2.6 APK 内部文件浏览（**不含任何逆向**）

- 打开 APK = 打开 ZIP（`ZipFile`）+ 结构化分组：
  | 分组 | 展示 | 操作 |
  |---|---|---|
  | `AndroidManifest.xml` | **Hex 预览**（默认）；附加「应用信息」卡片来自 `PackageManager.getPackageArchiveInfo()`（纯官方 API：包名、版本名/号、targetSdk、权限、图标、标签） | 无编辑 |
  | `classes*.dex` | 列表（Hex 只读预览） | 无编辑、无解析为类/方法 |
  | `res/`、`assets/` | 常规文件预览（图片、文本、字体、音频） | 解压/复制/分享 |
  | `lib/**` | 常规文件（Hex/属性） | 解压/复制 |
  | `META-INF/**` | 文本/证书指纹（`java.security.cert` 读 `CERT.RSA` 显示 SHA-256，只读） | 只读 |
  | `resources.arsc` | Hex 只读 | 无编辑 |
- 明确禁止：DEX 反编译、Arsc 编辑、资源替换、重打包、签名伪造；设置页与预览页均有一行说明文案。

#### 9.2.7 Hex 编辑器（`HexView`，自绘）

- 视图：`偏移(8) | 十六进制(16×2) | ASCII(16)`，等宽字体，高亮当前行/选中范围，区分修改字节（红/绿）。
- 加载：分页 64 KB 窗口（LRU 缓存前后各 2 页），支持 GB 级文件；`VfsReader.readFully(offset, len)` 按需读，网络协议用 Range 精准读。
- 编辑（可选，仅当 `rangeWrite`）：修改字节 → 内存补丁表（offset → byte[]）→ 保存 = 读原文件 + 应用补丁写新文件（本地原子改名；网络写 `.part` → MOVE/rename）；撤销/重做栈；插入/删除（改变长度，风险提示）。
- 功能：跳转偏移、查找（HEX 模式 / ASCII / 正则不可用于 hex）、选择范围、复制 / 粘贴（文本或 hex）、导出选中为文件、随滚动显示文件大小/百分比。
- 只读模式：只读文件系统来源或 `rangeWrite=false` → 只读 Hex 查看（仍支持查找/跳转）。

#### 9.2.8 文本对比（`DiffEngine`）

- 算法：行级 `Myers diff`（`DiffUtils` 风格），大文件用「分块 + 前缀/后缀裁剪 + 哈希行号」加速；二进制或超阈值 → 提示改用 Hex 对比（可选）。
- 模式：并排（同步滚动）/ 统一（inline）；忽略空白/忽略大小写/忽略行尾（CRLF）。
- 交互：差异行上下跳转、只显示差异、两侧行号栏、命中数统计；结果可复制为 patch 文本。
- 入口：选中两个文件（左右窗格各一个）→ `⇄ → 比较文件`。

### 9.3 预览的通用规则

- 预览不落盘（除必要临时文件），全部通过 `Vfs` 流式读取；远程预览先取「前 64 KB + 元数据」快速出画面。
- 每种预览都有「另存为 / 分享 / 复制路径 / 属性 / 用其他方式打开」的统一底部操作栏。
- 预览会话生命周期与窗格绑定：切换文件复用同一个预览 Activity/Fragment 实例（避免重建开销）；退出时释放解码器/播放器。
- 预览失败（解码失败/权限/网络）→ 明确错误卡片 + 「重试 / 用系统应用打开 / 以 Hex 打开」三选一。

| 返回键 | 先退选择模式 → 再退目录（后退）→ 再退标签/主页 → 退出 |

### 10.3 反馈、撤销与错误处理

- 所有破坏性操作：Snackbar + **撤销**（本地删除走回收站可直接撤销；重命名/移动记录反向操作，10s 内可撤销；网络删除不可撤销 → 事前二次确认并在确认框写明）。
- 进度：命令栏上方常驻细进度条（当前任务），点击进入任务页；大任务出现「迷你悬浮进度胶囊」。
- 错误分级：
  - 提示级（可重试）：Snackbar + 「重试」；
  - 阻塞级（缺权限）：底部抽屉 + 明确按钮（「去授权」「用 SAF 授权此目录」「改用 Root」）；
  - 致命级（连接配置错误）：跳转到连接编辑页并高亮错误字段（密码/端口/协议）。
- 空态：目录为空 / 无网络 / 无任务 → 各有一句人话文案 + 一个主要动作。
- 无障碍：`contentDescription` 全覆盖、动态字号支持、TalkBack 可用（列表项朗读「名称，目录，12 项，修改于…」）。
- 视觉：Material 3 + 动态取色，明暗主题；扩展名图标配色表集中在 `:core:ui` 的 `FileIconMap`。

### 10.4 键鼠 / 大屏（P1）

- 外接键盘：`Ctrl+C/X/V`、`Delete`、`F2` 重命名、`F5` 刷新、`Tab` 切窗格、`Alt+←/→` 历史、`Ctrl+F` 搜索。
- 鼠标右键：上下文菜单；滚轮：列表滚动；拖拽同 §6.5。

### 11.3 安全

- `SecretStore`：Android Keystore 生成 `AES-256-GCM` 主密钥（别名 `panelfm.master.v1`），每条口令独立 IV，密文 Base64 存 `secret` 表（`secret_ref` 指向）；支持「导出配置不含口令」与「含口令（用导出密码二次加密）」两种导出。
- 私钥文件：导入后复制到应用私有目录，`chmod 600`，不写入外部存储。
- 不采集任何使用数据；日志默认在应用私有目录，含路径信息，导出前提示可能包含隐私。
- 备份：`allowBackup=true` 但排除 `secret` 表与私钥（`backup_rules.xml`）。

### 11.4 导入 / 导出

- 格式：`panelfm-config.json`（`kotlinx.serialization`）：

```json
{
  "version": 1,
  "exportedAt": 1759480000000,
  "connections": [ { "type": "sftp", "name": "NAS", "host": "192.168.28.156", "port": 22,
                     "user": "u", "basePath": "/home/u", "options": {"jumpHost": null},
                     "secret": {"kind": "plain", "value": "..."} } ],
  "bookmarks": [ ... ], "prefs": { ... }, "knownHosts": [ ... ]

```

## 13. 风险与对策

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| R1 | **Scoped Storage**：无「所有文件访问」时无法直读 `/storage/emulated/0` | 核心功能不可用 | 首启引导授权 `MANAGE_EXTERNAL_STORAGE`；拒绝则降级 `SafVfs`（可选根目录）+ 应用私有目录，并在 UI 常驻一个「授予完整访问」入口 |
| R2 | `/Android/data`、`/Android/obb` 在 API 30+ 无法直读 | 部分目录不可见 | 用 SAF 单独授权该子树；说明文案「系统限制，需 SAF 授权」；Root 可选 |
| R3 | **Android 17 `ACCESS_LOCAL_NETWORK` 未授权** → 局域网连接直接超时，报错难以自行定位 | 用户以为「协议坏了」 | 连接前检测 + 专门错误码 `LOCAL_NETWORK_DENIED` + 一键跳转授权；局域网扫描前也检查 |
| R4 | 协议碎片化（同一协议不同服务器行为不同） | 兼容性问题反复 | 能力位如实声明 + 运行期探测（首次连接做一次轻量探针）+ 「quirks 表」（按服务器 banner/`Server` 头打补丁）+ 详细协议日志可导出 |
| R5 | WebDAV 307/308 与方法改写、自签证书 | 上传失败 | 自研 `RedirectInterceptor`（保方法保 body、跨域剥 Authorization）；按 host 定制 `SSLSocketFactory` |
| R6 | SMB 库在 Android 上的可行性（JNA/DFS） | M5 卡住 | **M5 第一件事做 2 天 spike**：SMBJ vs jcifs-ng 用真机 NAS 验证（读写、随机读、大文件）；以 `SmbBackend` 抽象隔离，可随时换实现 |
| R7 | 大文件/大目录性能（GB 级读写、10 万条目录） | 卡顿、OOM | 流式 + 分页 + 稀疏索引；Hex/文本窗口化；列表虚拟化 + fast-scroll 跳过缩略图；Macrobenchmark 卡指标（启动 < 800ms，列表滚动 jank < 1%） |
| R8 | 传输中被系统杀/网络切换 | 任务中断、数据半成品 | 断点续传 + `.part` + `resume_entry` 持久化；前台服务 + WakeLock；网络切换策略；「已复制未删除」状态可恢复 |
| R9 | Compose 长列表在低端机掉帧 | 体验下降 | `key/contentType/@Immutable`、避免每项 `remember` 重建、预取；触发阈值（jank > 5%）→ 用 `AndroidView` 包 RecyclerView 替换 `DirectoryListContract` 实现 |
| R10 | 文本编辑器大文件（> 50 万行） | 崩溃/卡死 | 阈值以上强制只读 + 窗口化 + 后台索引；编辑模式限制 2 MB/20 万行并提示「用 Hex/外部编辑器」 |
| R11 | 依赖许可（junrar 的 UnRAR、jcifs-ng 的 LGPL） | 合规 | 只动态链接不改源码；许可清单页（`lib/licenses`）逐条列出；若介意可编译期开关移除 RAR |
| R12 | 中断式会话（FTP 控制连接在 NAT 上超时） | 长任务失败 | `NOOP` 心跳 + 自动重连 + 重连后从续传点继续；每次操作前检查连接活性 |
| R13 | 前台服务时长限制（Android 15+ dataSync 累计上限） | 长任务被打断 | 断点续传设计兜底 + 超时前提示用户 + 分批执行；可选「仅充电时」策略 |
| R14 | 单人项目范围失控 | 交付拖延 | 严格按里程碑；P2 项（Root、远程管理、MCP）默认不做；每个里程碑结束必须可安装、可用、可回滚 |
| R15 | 隐私/凭据泄露 | — | Keystore 加密、日志脱敏（URL 中的 user:pass 打码）、备份排除、导出可选不含口令 |

### 14.3 关键测试用例（示例，必须自动化）

1. 断点续传：起 100 MB 上传 → 传 40% 后强杀进程 → 重启 App → 任务恢复且从 40% 继续（按协议分别断言 `REST`/`seek`/`uploadId`）。
2. 校验符失配：目标文件被外部修改 → 续传必须放弃并重传（断言日志与 UI 标注）。
3. 取消语义：任意时刻取消 → 3 秒内停止，临时文件被清理，无泄漏线程。
4. 路径安全：`..` 遍历（FTP/DAV/SFTP）被拒绝；同名冲突四种策略的最终文件集合断言。
5. 同步按钮：宿主在 `archive://…!/x` 时，另一窗格跳到压缩包所在目录。
6. 拖拽语义：拖到目录空白 = MOVE，拖到文件行 = COPY（断言最终调用语义）。
7. 大目录：20k 项的列表滚动 > 55fps（测试机中位数）且内存 < 300 MB。
8. 预览分派：`a.jpg` → 图片；`.bin` → Hex；未知 `.xyz` → 「打开方式」；强制「以文本打开」生效。
9. APK：能列出 `classes.dex` 且只提供 Hex（断言不存在任何 DEX 解析入口）。
10. 权限矩阵：拒绝 `MANAGE_EXTERNAL_STORAGE` / 拒绝 `ACCESS_LOCAL_NETWORK` 两种路径下的 UI 引导正确。

### 14.4 质量门禁

- CI 必过：`detekt` + `ktlintCheck` + `lintDebug`（`abortOnError`）+ 单元/集成测试 + `assembleRelease` 成功。
- 覆盖率：`core:*` 行覆盖 ≥ 60%，`core:transfer` 与 `core:vfs-api` ≥ 75%。
- 提交前：`./gradlew test` 本地通过；协议相关改动必须附带真实服务器手测记录（写入 `docs/regression.md`）。

```kotlin
class FileOperationPlanner @Inject constructor(private val registry: VfsRegistry) {

    suspend fun plan(req: TransferRequest, onScan: (Int, Long) -> Unit): OperationPlan {
        val srcLease = registry.acquire(req.sources.first().accountId())
        val dstLease = registry.acquire(req.destDir.accountId())
        val sameVfs = srcLease.use().id == dstLease.use().id
        val items = mutableListOf<PlanItem>()
        var bytes = 0L
        for (s in req.sources) collect(s, dstDir = req.destDir, out = items) { n, b -> bytes += b; onScan(n, bytes) }
        return OperationPlan(
            items = items,
            fastPath = when {
                !sameVfs -> FastPath.NONE
                req.op == TransferOp.MOVE && srcLease.use().capabilities.rename -> FastPath.SERVER_MOVE
                req.op == TransferOp.COPY && srcLease.use().capabilities.serverSideCopy -> FastPath.SERVER_COPY
                else -> FastPath.NONE
            },
            relay = if (sameVfs) RelayMode.DIRECT else RelayMode.PIPE,
            totalBytes = bytes,
        )
    }

    /** 递归收集 + 前置安全校验（自包含、路径深度、保留名） */
    private suspend fun collect(src: VfsUri, dstDir: VfsUri, out: MutableList<PlanItem>, onScan: (Int, Long) -> Unit) { ... }
}
```

### 16.2 传输任务与闸门

```kotlin
class TransferTask internal constructor(
    val id: TaskId,
    private val req: TransferRequest,
    private val plan: OperationPlan,
    private val resumeDao: ResumeDao,
    private val conflictResolver: ConflictResolver,
    private val clock: Clock,
) {
    private val _state = MutableStateFlow<TaskState>(TaskState.Queued)
    val state: StateFlow<TaskState> = _state.asStateFlow()
    private val gate = TransferGate()        // pause / cancel / conflict-await

    suspend fun run(scope: CoroutineScope) {
        try {
            _state.value = TaskState.Planning(plan.items.size, plan.totalBytes)
            plan.items.forEachIndexed { i, item -> transferItem(i, item) }
            _state.value = TaskState.Done(okCount, failures, doneBytes, clock.elapsed())
        } catch (c: VfsException.Cancelled) {
            withContext(NonCancellable) { cleanupPartials() }
            _state.value = TaskState.Cancelled
        } catch (e: VfsException) {
            _state.value = TaskState.Failed(e)
        }
    }

    private suspend fun transferItem(index: Int, item: PlanItem) {
        val dst = resolveConflict(item)                       // OVERWRITE/SKIP/KEEP_BOTH/ASK
        val resume = resumeDao.find(taskId, index)            // 断点状态
        val offset = if (resume?.isValid(item) == true) resume.offsetDone else 0L
        registry.acquire(item.src).use().openRead(item.src, offset = offset).use { reader ->
            val writer = registry.acquire(dst).use().openWrite(dst, item.size, offset, item.contentType)
            writer.use {
                pump(reader, writer) { n ->
                    gate.checkpoint()                          // 暂停/取消/冲突在这里生效
                    reportProgress(n)
                    resumeDao.saveProgress(taskId, index, writer.writtenBytes, writer.checkpointToken())
                }
                writer.commit()
            }
        }
        if (req.op == TransferOp.MOVE) deleteSource(item)
    }
}

class TransferGate(private val scope: CoroutineScope) {
    suspend fun checkpoint()      // Paused → 挂起；Cancelled → throw Cancelled；Conflict → 挂起
    fun pause(); fun resume(); fun cancel(); fun awaitConflict(info: ConflictInfo)
}
```

```kotlin
class VfsDataSource(private val registry: VfsRegistry, private val opChain: TransferOpChain? = null) : DataSource {
    private var reader: VfsReader? = null
    private var uri: VfsUri? = null
    private var position = 0L

    override fun open(dataSpec: DataSpec): Long {
        val uri = VfsUri.parse(dataSpec.uri.toString())
        val r = registry.peekOrAcquire(uri).openRead(uri, offset = dataSpec.position)
        reader = r; position = dataSpec.position
        return if (dataSpec.length != C.LENGTH_UNSET.toLong()) dataSpec.length else (r.size ?: C.LENGTH_UNSET.toLong())
    }
    override fun read(buffer: ByteArray, offset: Int, length: Int): Int {
        val n = runBlocking { reader!!.read(buffer, offset, length) }
        if (n > 0) position += n
        return n
    }
    override fun getUri(): Uri? = uri?.toAndroidUri()
    override fun close() { runBlocking { reader?.close() }; reader = null }
}
```

**与本文档的偏差（有意为之，已在代码注释说明）**

1. **不用 Hilt / Room / KSP**：改用「手工 DI（`AppContainer`）+ SQLiteOpenHelper + DataStore」。
   理由：零注解处理器 → 构建快、版本耦合少；DAO 接口已隔离，后续要换 Room 只需替换实现。
2. **feature 层先落在 `:app`**（`app/src/main/kotlin/.../ui/*`），未拆成 `:feature:*` 模块。
   理由：单人项目减少模块数量；模块边界按 §15 预留，拆分是机械操作。
3. **AGP 9 的两个开关**：`android.builtInKotlin=false` + `android.newDsl=false`（配合经典 Kotlin Gradle Plugin 2.4.10 + Compose 编译器插件，版本严格对齐）。
4. **WebDAV 上传**：本轮为「管道流式整体 PUT」（`rangeWrite=false`），分片/断点续传上传留到 M2+ 增强。
