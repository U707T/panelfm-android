# 选择 / 多选交互（复刻 MT）——模型与手势说明

> 状态：**已实现**（v1.3.0）。本文是这套交互的**唯一设计说明**：语义依据、状态模型、
> 手势判定、与旧实现的差别、怎么验证。
>
> 语义依据只有两个来源：**MT 自己的字符串资源**（`/workspace/mt-analysis` §7.1）与本仓库代码。
> 凡是「猜」的地方都标了「取舍」，不写成「已对齐」。

---

## 1. MT 的行为（静态依据）

| 资源 | 文案 | 含义 |
|---|---|---|
| `0x7f1106f3` | 左右滑动文件可直接选择 | 滑动 = 进入多选（不需要先长按） |
| `0x7f11062f` | 滑动选择列表中任意两个文件，将会自动选择它们中间所有的文件 | 滑动定义区间（连选） |
| `0x7f110630` | 开启后点击列表中任意两个项，将会自动选择它们中间所有的项。 | 点击连选（设置项，默认关） |
| `0x7f110631` | 可通过分别长按两个项目来进行连选 | 长按连选 |
| `0x7f110697` | 右滑列表项可进行更多操作 | 已多选态右滑出菜单 |
| `0x7f11062b/632/633` | 全选 / 反选 / 类选 | 底栏按钮 |
| `0x7f11063b` | 已选: %d | 顶栏计数 |

三条核心语义（本实现的骨架）：

1. **滑动即模式切换**：在任意行上横滑 → 进入多选并选中该行；
2. **滑动定义区间**：按住不放继续滑 → 两次滑动之间的项全部选中（跟手，可回退取消）；
3. **点击切换状态**：多选态下单击 = 切换单项（开启「点击连选」后 = 与锚点连选）。

## 2. 状态模型

```
PaneState
 ├─ selection        : Set<String>        选中项（key = 列表项 uri，稳定标识，不用下标）
 ├─ selectionAnchor  : String?            长按连选锚点（0x7f110631）
 ├─ tapAnchor        : String?            点击连选锚点（0x7f110630）
 └─ selectionSweep   : MtSelection.Sweep? 正在进行的扫选会话（手指按住期间）
```

- **纯逻辑在 `core/common/MtSelection.kt`**（可单测，无 Compose / 无 Android 依赖）：
  `toggle` / `all` / `invert` / `rangeKeys` / `unionRange` / `beginSweep` / `swept`。
- **锚点与扫选会话跟着窗格走**：旧实现把两个锚点放在控制器上（全局字段），
  在左窗格长按后去右窗格长按，会连出一个跨窗格的区间 —— 现在不可能发生。
- 扫选会话的语义：`选择 = base ∪ [锚点 .. 当前行]`，`base` = 按下时已有的选择。
  所以**扫选是追加、不是替换**，而且手指往回滑时区间会收回去。
- 换目录 / 切标签页 / 清空选择都会把锚点与会话一起收掉（`PaneState.withSelectionCleared()`）。

## 3. 手势判定（`core/ui/MtRowGesture.kt`）

判定顺序（文档附录 F.5 的冲突消解顺序，全部可单测）：

| 优先级 | 手势 | 判定 | 结果 |
|---|---|---|---|
| 1 | 长按 | 按住 ≥ 400ms（松手才弹菜单） | 锚点 + 多选；长按第二项 = 连选 |
| 2 | 扫选 | 横向 ≥ 24dp 且 \|dx\| > 2\|dy\| | 进入多选 → 逐行区间 → 松手结束 |
| 3 | 右滑出菜单 | 已多选 + 右滑 ≥ 48dp 且 \|dy\| < 48dp（一次手势一次） | 更多操作 |
| 4 | 点按 | 松手时位移 < 12dp | 打开 / 预览；多选态 = 切换 |
| 5 | 纵向拖动 | 纵向过 touchSlop 且纵向占优 | 让位给列表滚动 |

实现要点：

- **手势挂在列表上，不挂在行上**（`PaneView.rowListGestures`）。
  `LazyColumn` 的行会随滚动被回收，行级手势一旦滚出屏幕就被取消 ——
  「扫到屏幕之外」根本做不完。MT 的结构也是挂在 ListView 上。
- **触摸走 Initial pass**：横滑进入多选后立刻消费事件，内层 `scrollable` 看到
  「已被消费」就不再纵向滚动（与旧的行级实现等价）。
- **边缘自动滚动**：手指停在列表上/下边缘 48dp 内，列表按帧滚动（最高 14dp/帧，
  越靠边越快），区间继续铺 —— 长列表可以一路扫到底。
  启动点在 `sweepAutoScroll`（组合作用域），因为 `pointerInput` 是**受限挂起作用域**，
  里面调不了 `scrollBy` / `withFrameNanos`。
- **跟手预览**：被扫到的那一行横向跟手位移（阻尼 0.25、上限 16dp、缩放最多 2%），
  抬手弹回；只影响那一行（动画值在 `graphicsLayer` 里读，其余行不参与重组）。
- **锚点取「按下的那一行」**，不是「跨过阈值那一刻手指所在的行」。

## 4. 与 v1.2.5（旧实现）的差别

| # | 旧行为 | 现在 | 为什么 |
|---|---|---|---|
| 1 | 扫选是**替换**语义：滑两下会抹掉之前选的项 | 追加（`base ∪ 区间`） | 与 `0x7f11062f` 的「将会自动选择」一致 |
| 2 | 区间只增不减 | 手指退回时区间收回去 | 跟手：划过 = 选中，退回 = 取消 |
| 3 | 锚点是 `PaneView` 的局部 `var`（重组/转屏就丢） | 进 `PaneState` | 状态该跟着数据走 |
| 4 | 长按 / 点击锚点是控制器的**全局**字段 | 每个窗格各一份 | 左右窗格不再串味 |
| 5 | 长按另一项会 `selection = setOf(key)`（推平已选项） | 已选中项只挪锚点，不推平 | 长按常用于「对当前选择集做操作」 |
| 6 | 连选区间是替换语义 | 追加（`selectRange`） | 同上 |
| 7 | 扫选滚不出屏幕 | 边缘自动滚动 | 长目录连选的刚需 |
| 8 | 手势判定混在行内 `when` 里，无法单测 | `MtRowGesture` 纯状态机 + 单测 | 改阈值不再靠手感回归 |
| 9 | 无跟手反馈 | 位移 + 缩放预览，抬手弹回 | 让用户看得出「正在划选哪一块」 |

## 5. 验证

**单测**（`./gradlew testDebugUnitTest --offline`，全量 281 例）：

- `core/common/.../MtSelectionTest.kt`（11）：追加语义、跟手撤回、锚点失效、反选补集…
- `core/ui/.../MtRowGestureTest.kt`（15）：点按 / 长按（含事件稀疏）/ 扫选三阶段 /
  菜单三条件 / 纵向让位 / 空白处不响应…
- `app/.../PaneGestureTest.kt`（4）：边缘滚动速度曲线（中间不滚、越靠边越快）。

**实机一分钟复核**（单测测不了手感，建议按这 6 条过一遍）：

1. 长按任意文件 → 震动 + 弹菜单；再长按**另一项** → 两项之间的全被选中，菜单随之变多选菜单；
2. 在任意行上左右滑 24dp → 立刻进入多选并选中该行，底部变「全选/反选/类选/取消」；
3. 按住继续上下滑 → 划过的行依次选中；**往回滑**能取消（跟手）；
4. 滑到列表底部边缘停住 → 列表自动滚动，区间继续延伸到屏幕外；
5. 已多选时右滑某一项 ≥ 48dp → 弹出该项的操作菜单（多选集保持不变）；
6. 普通上下滑 / 点击打开文件夹、返回上级 → 与之前一致（没被手势层挡住）。
