# 选择 / 多选交互（复刻 MT）——模型与手势说明

> 状态：**v1.9.0 重构**（此前的「跟手扫选」模型已废弃）。本文是这套交互的**唯一设计说明**：
> 语义依据、状态模型、手势判定、与其他实现的差别、怎么验证。
>
> 语义来源：**用户实机对照 MT 的口述确认**（见 §1，标注了对应的 MT 字符串）+ 本仓库代码。
> 历史教训写在 §5：早期版本只凭字符串推断出的三条交互，用户实机核对后**全部不成立**。

---

## 1. MT 的行为（用户实机确认 + 字符串对照）

| 操作 | 行为 | 对应 MT 字符串 |
|---|---|---|
| **长按**一项 | **立刻弹该项的二级菜单**（阈值 400ms 到达即弹，不等松手）；**不改选择、不进多选** | （菜单由 `0x7f0e00xx` 系列承载） |
| **左/右滑动**一项 | 震动 + 动效 → **进入多选并选中该行** | `0x7f1106f3` 左右滑动文件可直接选择 |
| 滑动一项后，**再滑动另一项** | 两项之间的**闭区间全部选中**（追加） | `0x7f11062f` 滑动选择列表中任意两个文件，将会自动选择它们中间所有的文件 |
| 滑动一项后，**点击**另一项 | 只是**把这两项都选中**（普通加选，不连区间） | ——（默认行为） |
| 多选态**点击** | 加 / 减选（toggle） | —— |
| 底栏 | 全选 / 反选 / 类选 / 取消 | `0x7f11062b/632/633` |
| 「点击连选」设置开启后点击两项 | 区间连选（**设置项，默认关**） | `0x7f110630` 开启后点击列表中任意两个项，将会自动选择它们中间所有的项。 |

**三条核心语义**（本实现的骨架）：

1. **长按 = 弹菜单**：与选择完全解耦（旧实现长按会进入多选、还会改选择）；
2. **滑动是离散动作**：一次滑动 = 选中那一行；滑动触发后这次触摸就"结束"了
   （吞掉后续事件到手指抬起）—— **没有「按住一路刷」的跟手扫选**；
3. **连选只发生在「滑动 + 滑动」之间**：滑动设锚点，再滑动就连成区间；
   点击不会触发连选（且点击会清掉滑动锚点，避免之后一次滑动把区间接到老锚点上）。

## 2. 状态模型

```
PaneState
 ├─ selection        : Set<String>   选中项（key = 列表项 uri，稳定标识，不用下标）
 ├─ selectionAnchor  : String?       **滑动锚点**（上一次「左右滑动选中」落在哪一项）
 └─ tapAnchor        : String?       「点击连选」的锚点（0x7f110630，默认关）
```

- **纯逻辑在 `core/common/MtSelection.kt`**（可单测，无 Compose / 无 Android 依赖）：
  `toggle` / `all` / `invert` / `rangeKeys` / `unionRange` / `swipe`。
- **锚点跟着窗格走**：旧实现把锚点放在控制器上（全局字段），左窗格滑动后去右窗格滑动，
  会连出一个跨窗格的区间 —— 现在不可能发生。
- 滑动锚点的生命周期：**滑动**时设置/前移；**点击**（含「点击连选」分支）时清空；
  换目录 / 切标签页 / 清空选择 / 全选 / 反选 / 类选时清空
  （`PaneState.withSelectionCleared()` 与控制器各入口负责）。
- 锚点失效（列表刷新后那一项不在了）时，`MtSelection.swipe` 退化为「只选这一项」——
  宁可不连，也不在错误的区间上乱选。

## 3. 手势判定（`core/ui/MtRowGesture.kt`）

| 优先级 | 手势 | 判定 | 结果 |
|---|---|---|---|
| 1 | 长按 | 按住 ≥ 400ms（位移 < 12dp） | 震动 + **立即弹二级菜单**（不改选择） |
| 2 | 滑动选中 | 横向 ≥ 24dp 且 \|dx\| > 2\|dy\| | 震动 + 进入多选 / 与滑动锚点连成区间（一次手势只触发一次） |
| 3 | 点按 | 松手时位移 < 12dp | 打开 / 预览；多选态 = 加/减选 |
| 4 | 纵向拖动 | 纵向过 touchSlop 且纵向占优 | 让位给列表滚动 |

实现要点：

- **手势挂在列表上，不挂在行上**（`PaneView.rowListGestures`）。行级节点在 `LazyColumn`
  里会随滚动被回收，手势会跟着被取消；MT 的结构也是挂在 ListView 上。
  行里只保留 `clearAndSetSemantics` 的点击 / 长按**无障碍语义**（不是触摸处理器）。
- **触摸走 Initial pass**：长按弹菜单 / 滑动选中触发后立刻消费事件，
  内层 `scrollable` 与行的语义动作都不会再收到这次触摸的其余部分。
- **长按在阈值那一刻派发**（不等松手）：与系统 `View.setOnLongClickListener` 一致，
  也是用户说的"快速出来二级菜单"。事件稀疏（按住 500ms 直接松手、中途没有 MOVE）时
  在松手那一帧补判。
- **滑动是"一次性"的**：`Phase.SWIPED` 持续吞事件到手指抬起，同一手势不会连发；
  没有跟手预览、没有边缘自动滚动（那两样属于已废弃的连续扫选模型）。
- **一次触摸 = 一遍手势循环，抬手必须退出**（`PaneGestures.detectRowGesture`）：Compose 的
  `awaitEachGesture` 在手势块返回后要用 `awaitAllPointersUp()` 收尾；块若不退出，下一次触摸
  的第一个事件会被旧循环收到（PointerId 每次触摸都是新值）→ 整段触摸在「等抬手」里被吞掉。
  实机表现即**「滑动选择必须滑 2 次」「滑第二项有一整段固定无响应」**（发版后用户上报，
  已修；回归用例 `RowGestureWiringTest`）。这是接线层唯一手写的生命周期，改动前先读注释。
- **滑动动效**：被选中的那一行朝滑动方向轻推 12dp 再弹回（`MtGesture.SwipeAnimDp`，
  高刚度弹簧）；只影响那一行。

## 4. 与 v1.3.0–v1.8.x（旧实现）的差别

| # | 旧行为 | 现在 | 为什么 |
|---|---|---|---|
| 1 | 长按 400ms → 松手才弹菜单，并且**顺带进入多选 / 改选择** | 长按 = 只弹菜单（阈值即弹） | 用户实机确认：MT 长按就是弹二级菜单 |
| 2 | 长按第二项 = 连选区间（`0x7f110631` 推断） | 移除；连选只由「滑动 + 滑动」触发 | 该文案与 `0x7f11062e`（长按两个**类**连选）是同一套，属于按类分组的列表（DEX 类列表），不在文件列表上（用户实机确认） |
| 3 | 左右滑动 → **跟手扫选**（按住一路刷、可回退、边缘自动滚动） | 滑动 = 离散选中；再滑另一项 = 连区间 | 用户实机确认："这样会导致很多误触，MT 不是这样" |
| 4 | 已多选时右滑 ≥48dp → 弹该项菜单（`0x7f110697` 推断） | 移除（更多操作只由长按触发） | 用户实机确认 |
| 5 | 扫选会连出屏幕之外的项（边缘自动滚动） | 不做（要选远处就滚过去再滑一次） | 同上 |
| 6 | 点击后滑动锚点残留，之后一次滑动可能连出大段区间 | 点击 / 全选 / 反选 / 类选 / 换目录都清锚点 | 「点击不连选」的语义要封闭 |

保留不变：多选底栏（全选 / 反选 / 类选 / 取消）、顶栏计数 `已选: %d`、
`0x7f110630`「点击连选」设置（默认关）、点按打开 / 预览、纵向滚动。

## 5. 历史教训（为什么会有这一版）

v1.3.0 的选择模型**只依据 MT 的字符串资源**推断（`0x7f1106f3/62f/631/697`），
把"左右滑动文件可直接选择"理解成"按住一路刷的跟手扫选"、把"可通过分别长按两个项目
来进行连选"当成文件列表的长按行为、把"右滑列表项可进行更多操作"当成多选态的右滑菜单。
**用户实机对照 MT 后发现这三条都不成立**，并且跟手扫选在实际使用中是明显的误触来源。

结论（写进流程）：涉及**手势 / 手感**的语义，字符串只能给线索，
**必须按「用户实机确认」定稿**；推断出来的交互要在文档里显式标注不确定。

## 6. 验证

**单测**（全量 `./gradlew testDebugUnitTest`）：

- `core/common/.../MtSelectionTest.kt`：滑动选中（首次只选它 / 第二次连区间 / 第三次延伸 /
  同项不误扩 / 锚点失效退化 / 追加不推翻）、切换、反选、区间边界；
- `core/ui/.../MtRowGestureTest.kt`：点按 / 长按（阈值即弹、事件稀疏、空白处不弹、
  弹后不再误触发）/ 滑动选中（方向、只触发一次、空白处不算、横向占优判定）/ 纵向让位；
- `core/ui/.../MtGestureTest.kt`：阈值常量（400ms / 12dp / 24dp / 12dp 动效）。
- `app/.../RowGestureWiringTest.kt`：接线层触摸生命周期（用假 `PointerInputScope` 驱动
  **真实**的 `awaitEachGesture` + `detectRowGesture`，复刻「每次触摸换新 PointerId」）——
  滑动 / 长按之后的下一次触摸不许被吞；空白处点按不许消费事件。

**实机一分钟复核**（单测测不了手感，建议按这 7 条过一遍）：

1. **长按**任意文件 → 震动 + **立刻**弹出该项二级菜单；选择没变化（没有勾选任何项）；
2. **左右滑动**一行 → 震动 + 行动效，该行被选中，底部出现「全选 / 反选 / 类选 / 取消」；
3. 再**滑动**另一行（可以先滚列表）→ 两次滑动之间的项全部被选中；
   **第二次滑动必须立即生效** —— 不允许「滑两下才算一次」或中间有一小段没反应；
4. **滑动**一项后**点击**另一项 → 只多选这一项（**不**连区间）；
5. 多选态点击已选中项 → 取消；点击未选中项 → 选中；
6. 普通上下滑 / 点击打开文件夹、返回上级、长按空白处 → 与之前一致（不误弹菜单、不误选）；
7. **长按**弹过菜单之后的**下一次**触摸（点按 / 滑动 / 滚动起手）必须立即生效
   （不允许第一下没反应 —— 与第 3 条同族的问题）。
