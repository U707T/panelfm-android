# PanelFM × MT 2.14.5 对齐复审查结果（2026-10-06）

> **一句话结论**：PanelFM 在「文件管理主链路」（双窗格 / 选择手势 / 传输 / 冲突 / 批量重命名 /
> 搜索 / 排序 / 权限 / 压缩解压 / 打开方式 / 属性）已经与 MT 基本对齐；**剩余未对齐项集中在

## 1. P1 —— 建议尽快对齐

### 1.1 文本编辑器：缺「另存为 / 重新加载（指定编码）/ 换行符 / 统计」

**MT 证据（B 级，逐条为 MT 字符串资源原文）**：

| 资源 | 文案 | 说明 |
|---|---|---|
| `0x7f11041a` | 另存为 | 编辑器菜单项 |
| `0x7f110413` / `0x7f110414` | 重新加载文件 / 当前文件已被修改，是否放弃修改内容并重新加载文件？ | 确认链完整 |
| `0x7f110415` | 指定编码重新加载 | 按用户选择的编码重读 |
| `0x7f110421` | 指定保存的编码 | 保存时按选择的编码写回 |
| `0x7f110391` | 换行符 | CRLF/LF 切换 |
| `0x7f110429` / `0x7f11042a` | 统计 / 字节数：%1$d\n字符数：%2$d\n单词数：%3$d\n中文数：%4$d\n总行数：%5$d | 统计对话框（5 项指标） |

**PanelFM 现状（可复核）**：

- `EditorScreen.kt:549` 的 `EditorMenu` 菜单项**全集**：保存 / 查找·替换 / 转到指定行 / 行操作（复制行、
  剪切行、删除行、清空行、重复行、大写、小写、增缩进、减缩进、切换注释）/ 代码整理（压缩、格式化）。
  **没有**另存为、重新加载、编码、换行符、统计。
- 编码是**自动识别**（`EditorScreen.kt:100` `charset` 状态，界面只读展示）；保存固定写回原 URI。
- 全仓 grep：`另存为` `重新加载`（编辑器语境）`换行符` `统计`（编辑器语境）→ **0 命中**。
- 顶部信息行已有「N 行 · M 字符 · charset」（`EditorScreen.kt:454` 附近），与 MT 的**统计**相比缺
  字节数 / 单词数 / 中文数，也没有独立对话框。

**影响**：遇到 GBK/UTF-16 误判、行尾符不一致（git 报 whole-file diff）、想留底不改原文件、
想核对字数的场景**无路可走**——这些恰是 MT 编辑器的高频入口。

**建议（一个批次做完 4 项，都是纯逻辑 + 对话框）**：

1. 菜单加「另存为」（目标选择复用「选择当前目录」`PickDirPurpose` 或输入路径对话框）；
2. 「重新加载」+ 改动确认（MT 原文 `0x7f110414`）与「指定编码重新加载」（编码选择复用现有
   `TextEncodings` 列表）；
3. 「换行符」切换（保存时按选择写 CRLF/LF；加载时检测并在状态栏显示当前行尾）；
4. 「统计」对话框（字节 / 字符 / 单词 / 中文 / 总行数，按 MT 的 5 项）。

**验收**：UTF-16 文件按 UTF-8 打开乱码 → 「指定编码重新加载 UTF-16」正确显示；CRLF 文件保存为 LF 后
`git diff` 不再全红；统计数值与 `wc -c/-m/-w/-l`（单词/中文按 MT 口径）逐项对得上；另存为不修改源文件。

### 1.2 目录对比：结果只有「前 40 条」，缺 MT 的分类 / 过滤 / 导出

**MT 证据**：

- **B 级**：`0x7f11014d`–`0x7f110151` 五个分类标题：**新增的文件 / 修改的文件 / 移动的文件 / 删除的文件 /
  相同的文件**；`0x7f1100ee`「对比结果」；`0x7f110149`「这两个文件存在许多差异，可能会花费较长计算时间，
  是否继续？」（大结果先确认）。
- **C 级**：菜单 `0x7f0e0000` 含 **导出 / 隐藏新增加文件 / 隐藏已删除文件 / 隐藏被修改文件** —— 对比结果页
  有按类别过滤的开关。

**PanelFM 现状（可复核）**：

- `FolderDiff.kt`：`DiffState { ONLY_LEFT, ONLY_RIGHT, DIFFERENT, IDENTICAL }`；对话框只显示
  **前 40 条差异**（`take(40)` + 「…（只列出差异项前 40 条）」），动作只有「仅复制左侧 / 只复制较新」。
- **没有**「移动的文件」探测（改名/移动无法识别）；没有分类切换、没有导出、没有大结果确认；
  `diffZipEntries`（`DiffScreens.kt:72`）**定义了但没有调用点**（ZIP 对比未接线）。

**影响**：大目录对比「看不到全貌、没法按需过滤、结果留不下来」；MT 的对比结果页是用途完整的工具。

**建议**：结果页从 AlertDialog 升级为独立页面——分类计数头部 + 过滤 chips（对应 MT 的三个"隐藏"开关）+
「相同」列表可折叠 + 「导出为文本」；补「移动的文件」识别（同大小+同内容哈希按名匹配）；接上 ZIP 对比入口。

**验收**：两个含 500 项、其中 3 项改名的目录对比：分类计数正确、改名项出现在「移动的文件」、
导出的文本可对账、`diffZipEntries` 有实际入口或删除。

### 1.3 搜索：文件名不支持通配符 `*` `?`

**MT 证据（B 级）**：`0x7f11061c`「欲搜索文件名 **(支持通配符\*和?)**」—— MT 的搜索输入框明确支持
通配符；另有 `0x7f110618`「在当前路径中搜索」/ `0x7f11061a`「在选中的文件夹中搜索」两个入口文案。

**PanelFM 现状（可复核）**：

- `SearchDialog.kt:33` 三种搜索类型（文件名包含的文本 / 文件名匹配正则 / 文件内容包含的文本）；
- `BrowserController.kt:755` `matchesSearch()` 只认：普通文本（contains）、`!否定`、`/正则`、`!/正则`——
  **没有 `*` / `?` 展开**（输入 `*.mp4` 只会按字面量匹配）。
- 搜索入口只有当前位置（⋮ → 搜索 / 结果页「二次搜索」），没有「在选中的文件夹中搜索」。

**建议**：NAME 模式识别通配符（含 `*`/`?` 时转正则或走 fnmatch，注意转义与 `[`、`.`）并补单测；
顺带把「选中文件夹 → 搜索此文件夹」加入长按菜单（MT 有该入口文案，但唤出位置 **D** 不可静态判定）。

**验收**：搜索 `*.mp4`、`img_?.jpg`、`r*eport` 结果正确；`C++`、`a.b` 等含特殊字符的查询行为不回归。

## 2. P2 —— 值得对齐

### 2.1 校验：「粘贴并校验」缺失

- **MT 证据**：布局 `0x7f0c009e`（A/C 级）实测包含：文件名输入框、MD5/SHA1/SHA256/CRC32 四个
  「输入框 + 复制按钮」，以及 **「粘贴并校验」** 行（输入框 + 粘贴按钮 + 状态文字 `0x7f090437`）。
  文案：`0x7f11050c` 粘贴并校验 / `0x7f110669` 校验通过 / `0x7f110664` 校验不通过。
- **PanelFM 现状**：`Dialogs.kt:526` `MessageDialog`（只读 + 复制）承载全部校验值与工具结果；
  **无法把外部得到的校验值粘进来比对**。
- **建议**：校验值结果对话框加「粘贴并校验」输入 + 通过/不通过提示（截断/空白容错、大小写不敏感），
  或做 MT 同构的专用「校验」对话框（一次算四种值）。
- **验收**：粘贴正确 MD5 →「校验通过」；改一位 →「校验不通过」；CRC32 八位十六进制大写/小写都接受。

### 2.2 所有者与用户组（chown 对话框）缺失

- **MT 证据**：布局 `0x7f0c0095`「所有者」（所有者 / 用户组两个下拉 + ☑ 同时应用到所有子文件 /
  ☑ 同时应用到所有子文件夹，`0x7f1100a3/0a4`）；文案 `0x7f110408`「所有者与用户组」。
- **PanelFM 现状**：`PropertiesDialog`（`Dialogs.kt:264`）只**显示**所有者/用户组；
  `MtPermissionDialog` 只管 mode（chmod）；VFS 层没有 setOwner API（grep `chown|setOwner` → 0）。
- **建议**：本地卷 + SFTP 增加入口（Android 非 root 下只能改自己拥有的文件，失败给可读文案）；
  递归勾选与权限对话框同款。若决定不做（Android 权限模型限制），在本文标记为「不做」并移除误导预期。
- **验收**：本地文件 chown 到当前用户成功；无权限场景给可读错误而不是 silent fail。

### 2.3 书签体系：分组 / 手动新建 / 批量删除 / 侧拉栏区块

- **MT 证据（B 级）**：
  - `0x7f110026` 添加分组；`0x7f1101a0` 是否删除分组「%s」？\n删除后该分组内的书签将被移动到默认分组中；
  - 菜单 `0x7f0e001a`：**添加 / 新建 / 从剪贴板导入**（书签列表的菜单，归属界面 **D** 不可静态判定，
    与上面两条文案互为旁证）；
  - `0x7f110028` 是否将选中的 %d 个文件添加到书签？ / `0x7f11002a` 添加书签成功 / `0x7f1105a8`
    是否删除选中的 %d 个书签？（多选批量删除）；
  - `0x7f110648` 在侧拉栏显示书签 / `0x7f110649` 仅显示默认分组的书签，查看全部书签请从底部工具栏上滑。
- **PanelFM 现状**：`BookmarkDao.kt:7` 的 `Bookmark` 数据类**没有分组字段**；`BookmarksScreen.kt`
  只有（打开 / 删除 / 长按拖动排序）；`BrowserController.addBookmark()` 只添加**当前目录**
  （不能把选中的文件批量加书签）；侧拉栏没有书签区块（只有底部上滑入口）。
- **建议（可拆两步）**：
  1. 数据层加 `group` 字段 + 分组 UI（默认分组 / 删除分组回落到默认分组，照 MT 文案）；
  2. 手动新建/编辑书签（名称 + 路径）、从剪贴板导入、多选删除；「在侧拉栏显示书签」开关（只显示默认分组）。
- **验收**：新建分组、移入、删除分组后书签回到默认分组；选中 3 个文件「添加书签」出现 3 条；
  侧拉栏开关生效且「上滑查看全部」可达。

### 2.4 应用管理：批量提取安装包 / 命名表达式 / 卸载

- **MT 证据（B 级）**：`0x7f110247` 安装包提取 / `0x7f110248` 提取安装包 / `0x7f110249` 是否提取选中的
  %d 个安装包文件？ / `0x7f11024a` 存放路径 / `0x7f11024b` 命名表达式 / `0x7f11024c` 命名表达式中必须
  至少包含一个名称变量！ / `0x7f11024d`「{A} 应用名称 {V} 版本名称\n{P} 应用包名 {C} 版本号」；
  `0x7f110719` 卸载 / `0x7f11071a` 是否卸载 %s ? / `0x7f11071b` 卸载成功。
- **PanelFM 现状**：`ToolsScreens.kt:151` `AppsScreen` —— 列表 + 点击单个导出（v1.4.0 起同名自动
  `名称 (1).apk`）；**无多选批量、无命名表达式、无卸载、无"打开/应用信息"**。
- **建议**：加多选 + 「提取」底部动作（存放路径 = 当前窗格目录 + 命名表达式，默认 `{A}{V}`）；
  卸载走 `Intent.ACTION_DELETE` + 二次确认（MT 文案同款）。
- **验收**：选中 3 个应用批量导出为 `名称_版本.apk`；表达式缺变量名时被拦下并提示（MT 原文）。

### 2.5 十六进制：只读 8KB → 至少可分页浏览（编辑单独议）

- **MT 证据**：`0x7f1107b5`「十六进制编辑器」（VIP 功能列表中出现，B 级）；`0x7f1100f1`「十六进制」
  （内置打开方式类型）；`0x7f11021d`/`0x7f110227` 启用二进制转换 / 启用八进制转换（转换类设置，
  对应 Hex 查看器的进制显示）；`0x7f1100d9` 大端模式。
- **PanelFM 现状**：`PreviewScreen.kt:248` `HEX_WINDOW = 8 * 1024` —— **前 8KB、只读**，
  标题即写「前 8 KB（只读）」；好处是已有解释器面板（大端模式等）。
- **建议**：第一步「可分页 / 按需加载的只读浏览」（与 MT 一样能翻全文件，这是现状最痛的点）；
  第二步再评估「编辑 + 写回」（需要原子替换 + 备份，风险批次单列）。
- **验收**：打开 200MB 文件能翻到尾部；偏移地址连续正确；大端解释器不回归。

## 6. 有意不做的差异（明确排除，不再逐版重提）

> 与旧文档一致；每一条都是产品边界决策，**不是遗漏**。

1. **逆向工程套件**：DEX/ARSC/AXML 编辑器、Smali 编译、寄存器、混淆对抗、签名工具、点九编辑、
   Svg→Xml、XML 批量替换、安装包优化/共存 —— PanelFM 明确不做（主页「关于」已声明）。
2. **账号体系**：登录/VIP/云备份/邮箱激活/插件平台 —— 不做。
3. **特权能力**：Root / Shell / Shizuku / 挂载读写 / 自定义 su —— 不做。
4. **终端模拟器** —— 不做（MT 的会话/扩展包体系一并排除）。
5. **系统剪贴板互通**：PanelFM 用应用内 URI 剪贴板（可表达多项 + 移动语义），不与系统 `ClipData`
   互转 —— 有意的安全/可移植取舍（旧文档已记录）。
6. **字典/翻译/语法文件管理**（`0x7f1101f7` 字典管理 / `0x7f11069e` 语法文件管理 / `0x7f110454` MT语法文件）
   —— 不做（编辑器语法是内置白名单）。
7. **悬浮窗/悬浮球**（`0x7f110225/2a0/4a3`）—— MT 用于后台快速入口；PanelFM 使用前台服务通知，
   不做悬浮球。
8. **脚本执行器**（`0x7f11060d/60e`）—— 不做。
9. **本地存储 SAF 授权**（`0x7f110211/72a/72b/039`）—— 暂缓（Android 11+ 全量访问已用
   「所有文件访问」权限覆盖；旧死入口已于 v1.3.3 移除）。
