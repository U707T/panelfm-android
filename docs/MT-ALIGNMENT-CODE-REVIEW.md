## 1. 本轮已核实并修复

### 1.1 传输引擎（P0，数据安全）

| 项目 | 原问题 | 当前处理 |
|---|---|---|
| 同名目录 | 慢路径目录项直接 `mkdir`，绕过覆盖/跳过/保留两者；`KEEP_BOTH` 时子项仍写入旧目录 | 顶层目录冲突先解析；保存 `source → target` 映射；`KEEP_BOTH` 整棵子树重映射，`SKIP` 阻止子项继续执行；已有目录采用逐项合并 |
| 覆盖删除 | `delete()` 失败被 `runCatching` 吞掉，随后仍然打开目标写入 | 删除失败立即中止；删除返回后再次 `stat`，目标仍存在也中止 |
| 自身复制 | 目标与源相同可能先删目标，导致源数据丢失 | 在任何 `stat/delete` 前做同一挂载点 + 同路径保护 |
| 错误识别 | 所有 `stat` 异常都被当成“不存在”，认证/断网可能被误判为可写目标 | 仅 `VfsException.NotFound` 被视为不存在，其它异常继续抛出 |
| 流生命周期 | `openRead` 成功、`openWrite` 失败时 reader 未关闭 | writer nullable + `finally` 关闭 reader；writer 异常路径按能力选择保留断点或 abort |
| 校验模式 | `VerifyMode` 只有模型字段，实际从未执行 | `SIZE` 校验目标长度；`HASH` 对源/目标做 SHA-256 流式校验；校验失败不会清除断点记录 |
| 修改时间 | 快路径服务端复制未补回源 mtime | 快路径复制成功后按计划树回写 mtime（目标协议支持时） |
| 同主机多账号 | `sameMount` 只比较 scheme/authority，两个 `?c=` 连接可能被当成同一挂载点 | `sameMount` 纳入连接 ID；不同账号/根路径不会触发自包含和自身覆盖保护的误判 |

新增回归覆盖：目录 `KEEP_BOTH` 子树映射、目录 `SKIP`、删除失败、writer 打开失败 reader 关闭、HASH 校验、同连接号边界。

### 1.2 压缩包与远程分享安全

- `ArchiveVfs` 拒绝绝对路径和含 `..` 的压缩包条目，防止恶意 ZIP 在解压时穿越目标目录。
- `ZipEditor` 对已有条目、重命名结果、添加条目统一做相对安全路径校验；压缩包内“完整路径重命名”不再能写入 `../...`。
- `RemoteHttpServer` 修复分享子目录时使用 `withPath` 替换根路径的问题；HTTP 路径现在相对启动时的分享根解析，不会因访问 `/` 暴露整个卷。
- `VfsRegistry` 改用并发容器；会话 key 纳入 secret 指纹，修改密码后不会复用旧认证会话；按连接基 key 断开时会清理不同 secret 版本的会话。
- Media3 VFS 数据源在 `openRead` 失败时不再发送没有对应 `transferStarted` 的 `transferEnded` 事件；用户已有的控制栏错误态修复保留。

## 3. 仍然不是“完全 1:1”的项

这些是明确的剩余差异，不应在发布说明中写成“已全部对齐”：

1. **SFTP 编码字段目前主要是 UI/配置兼容项**：FTP 已将编码用于控制连接；SFTP 的 MINA SSHD 文件名解码仍由协议库处理，尚未实现 MT 式任意编码转换。
2. **连接测试卡住引导**：目前有测试中/成功/失败状态，但尚未按 MT 在超过阈值后追加“尝试切换主/被动模式”的延时诊断文案。
3. **缩略图高级设置**：网络大小阈值和超时取消仍有硬编码/覆盖不足，属于体验项，不影响文件正确性。
4. **系统剪贴板**：PanelFM 的多项剪贴板是应用内 URI 模型，不能直接与系统文件管理器的 `ClipData` 互通；这是有意的安全/可移植取舍。
5. **MT 的逆向专属能力**：Dex/ARSC/AXML、插件、账号/VIP、Root/Shizuku、云备份不属于 PanelFM 产品范围。

## 4. Code Review 规则（后续改动必须遵守）

- 任何覆盖操作都必须先确认目标状态；不能吞掉 `delete/rename/stat` 异常后继续写。
- 任何 `openRead/openWrite` 都必须在异常、取消、校验失败路径关闭/abort；网络协议不能嵌套持有互斥控制通道。
- 任何跨目录/跨协议操作必须用统一 `TransferTask`，不能在 UI 里另写一套复制/移动逻辑。
- 任何来自压缩包、远端列表或 HTTP 的路径都按不可信输入处理；写入 ZIP 或本地目标前必须拒绝绝对路径和 `..` 段。
- 新增连接会话时必须考虑 secret 变化、同主机多账号、断开和空闲回收；不能只用 host/port 做身份。
- 参考 MT 文案时区分“资源/布局事实”和“根据行为推断的语义”，推断项必须在代码或测试中有落点。
